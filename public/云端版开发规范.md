# 云端版开发规范

> 本文档记录云端版（tcm-prescription-system）药品管理模块的永久性开发规范，所有后续修改须遵循以下标准。

## 一、Excel/CSV 导入解析规范

### 1.1 列对应关系（严格）

| 列 | 字段 | 说明 |
|----|------|------|
| A 列 (row[0]) | name | 药品名称 |
| B 列 (row[1]) | code | 简码 |
| C 列 (row[2]) | costPrice | **进价**（用户称 purchasePrice） |
| D 列 (row[3]) | price | 单价 |
| E 列 (row[4]) | unit | 单位 |
| F 列 (row[5]) | dosage | 常用用量 |
| G 列 (row[6]) | stock | 库存 |

### 1.2 进价校验规范

- C 列为空或非数字时：**禁止自动填充 0**，将 `costPrice` 设为 `null`
- 记录异常药材名称到 `missingPriceMedicines` 列表
- 统一使用 `parseMedicineRow(row)` 辅助函数解析，确保 Excel/CSV/JSON 三种导入路径行为一致

### 1.3 导入完成统计弹窗规范

导入完成后必须展示统计信息：
- 成功导入条数（进价完整）
- 进价缺失条数
- 异常药材名称列表（如有）

### 1.4 导入后自动同步

- 导入完成后调用 `saveMedicinesToCloud(medicines)` 保存到云端
- 保存成功后调用 `getMedicinesFromCloud(true)` 强制刷新（绕过缓存）
- 重新渲染药品列表，无需手动刷新页面

## 二、前端渲染规范

### 2.1 进价字段渲染

- **禁止固定写死进价 0 默认值**
- `costPrice` 为 `null`/`undefined`/空字符串时显示红色"未设置"提示
- 有值时正常显示数值 + "元"

### 2.2 编辑/新增药品进价输入

- 编辑药品时，进价 prompt 默认值使用现有值（无值时为空字符串，非 '0'）
- 新增药品时，进价 prompt 无默认值
- 用户留空时 `costPrice` 设为 `null`，非 `0`

## 三、缓存优化规范

### 3.1 URL 时间戳

- `getMedicinesFromCloud` 和 `getFormulasFromCloud` 的请求 URL 必须拼接 `?_t=${Date.now()}` 时间戳
- 目的：绕过浏览器缓存，解决手机端价格不更新问题

### 3.2 刷新药品库按钮

- 药品管理弹窗必须包含【刷新药品库】按钮（绿色）
- 点击后调用 `refreshMedicineLibrary()` 函数
- 该函数强制从云端拉取最新数据（`forceRefresh=true`）并重新渲染

### 3.3 数据变更后云端同步

以下操作完成后必须调用 `saveMedicinesToCloud(medicines)`：
- 新增药品（`showAddMedicineForm`）
- 编辑药品（`editMedicine`）
- 删除药品（`deleteMedicine`）
- 清空药物库（`clearMedicineLibrary`）
- 导入药品（`processImportedMedicines`）

## 四、验收核对项

## 七、全项目通用规范 - IndexedDB 篇

> 本节适用于所有端（云端网页/云端桌面/云端 APP/离线桌面/离线 APP），所有涉及 IndexedDB 的代码修改须遵循以下规则。

### 7.1 背景

2026-07-19 修复"退出登入后再次登入历史处方消失"问题（commit `aee66f3`，第6轮），根因是 `db-adapter.js` 用 DB_VERSION=2 自动初始化打开 PrescriptionDB 并保持连接，没有 `onversionchange` 处理器，导致 `index.html` 用 DB_VERSION=3 打开时被阻塞，触发 onblocked → 3s 超时 → `getAllPrescriptionsFromDB` 失败 → 处方消失。前 5 轮修复均未触及根因。

### 7.2 硬性规则（强制执行）

| # | 规则 | 说明 |
|---|------|------|
| 1 | **统一版本号** | 所有打开同一数据库的代码必须使用相同的 `DB_VERSION`，集中定义在一处（推荐放在 index.html 顶部） |
| 2 | **必须注册 `onversionchange`** | 所有 IndexedDB 连接都必须注册，收到版本升级通知时主动 `close()` |
| 3 | **禁止自动初始化** | 模块加载时不要自动执行有副作用的操作（如打开数据库连接），改为显式调用 |
| 4 | **避免多个模块打开同一数据库** | 整个应用只保留一个 IndexedDB 访问入口 |
| 5 | **定期清理"幽灵模块"** | 未被使用的代码应该删除，不要保留 |
| 6 | **新增模块时检查冲突** | 是否会与现有模块的资源（数据库/文件/连接）冲突 |
| 7 | **代码审查清单** | 每次新增 IndexedDB 相关代码时，检查上述 4 条规则 |

### 7.3 正确范例

```javascript
const DB_NAME = 'PrescriptionDB';
const DB_VERSION = 3;  // 规则 1：集中定义

function openDB() {
    return new Promise((resolve, reject) => {
        const request = indexedDB.open(DB_NAME, DB_VERSION);
        request.onsuccess = (event) => {
            const db = event.target.result;
            // 规则 2：必须注册 onversionchange
            db.onversionchange = () => {
                db.close();
            };
            resolve(db);
        };
        // ... 其他回调
    });
}

// 规则 3：禁止自动初始化
// ❌ DbAdapter.init().catch(...);  // 不要这样写
// ✅ 由调用方显式调用：await DbAdapter.init();
```

### 7.4 违反规则的后果

- 数据库连接被占用 → 版本升级失败 → IndexedDB 读取失败
- 处方数据"消失"（实际上是读取失败，数据仍在 IndexedDB 中）
- 多次修复无效（根因不在调用代码，而在连接占用）

### 7.5 安全防护规范

| # | 防护项 | 是否启用 | 理由 |
|---|---|---|---|
| 1 | 代码混淆（javascript-obfuscator） | ✅ 启用 | 不影响运行时行为，仅增加反编译难度 |
| 2 | 关键 API 校验（savePrescription/deleteHistory 等） | ✅ 启用 | 防止绕过登录直接调用 API |
| 3 | 控制流平坦化（controlFlowFlattening） | ❌ 禁用 | 破坏关键函数运行时行为 |
| 4 | 死代码注入（deadCodeInjection） | ❌ 禁用 | 影响性能，容易触发问题 |
| 5 | 字符串数组化（stringArray） | ✅ 启用 | 仅影响反编译，不影响运行 |
| 6 | 对象键名转换（transformObjectKeys） | ❌ 禁用 | 破坏对象访问 |
