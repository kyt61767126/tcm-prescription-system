## 1. 任务1（P1）：离线 APP 机构版顶部按钮显示「修改密码」，正确应为「用户管理」

### 现象（用户实测）
- 注册离线 APP 机构版 → 激活 → 登录后，顶部 tab 显示【修改密码】；规范要求机构版显示【用户管理】（KNOWLEDGE 2026-07-31 新规范；用户 profile：标准版→修改密码，机构版→用户管理）。

### 根因（已坐实 ~90%，下个会话可直接修复）
- **APP 端 `window.electronAPI` 桥没有 `getAppConfig` 方法**，两处注入均无：
  - `app_project/db-offline/app/app/src/main/java/com/benneng/pres/MainActivity.java` 的 `injectElectronApiShim`（L958-1044，electronAPI 对象无 getAppConfig 键）
  - `app_project/db-offline/app/app/src/main/assets/video-recorder-inject.js`（L142 覆盖的 electronAPI 同样无；已 rg 证实无命中）
  - 桌面 preload 有 `getAppConfig`（返回 userData config.json 权威配置）。
- 后果链：`index.html` L927 `if (window.electronAPI && window.electronAPI.getAppConfig)` 恒 false → **userData 权威 config 的异步加载整段不执行** → `CONFIG.edition` 恒为出厂 `personal`（L732 硬编码 + 同步 XHR 读 assets/config.json 也是 personal）→ `permission.js` L35 同样读不到 → `Permission._edition` 也恒 personal。
- 于是 `enforceStandardEditionButtons`（index.html L2784-2926）判定：configEdition=personal 不命中机构版豁免分支（L2852 INST_ED），`IS_DESKTOP_LOCAL`（桥注入 isElectron:true 且 APP_MODE=offline）→ `mustEnforce=true` → 强制执行标准版对齐 → 隐藏【用户管理】显示【修改密码】。
- 机构版标签（getEditionTag）可能也错显示「离线标准版」——同一根因，一并验证。

### 修复方向（建议）
1. **MainActivity.java 的 electronAPI shim 补 `getAppConfig`**：返回 filesDir `config.json` 的权威内容（含 edition=clinic / offline_clinic）。可复用/新增 `LicenseManager` 桥方法（读 `readConfigJSON()`，返回 `{success:true, config:{...}}`），注意排除敏感字段风险（前端本来就会拿 users，桌面 getAppConfig 也返回全量；但建议对齐桌面返回结构）。
2. video-recorder-inject.js 覆盖的 electronAPI 需同步保留 getAppConfig（它 Object.assign 或覆盖？L37 存 oldAPI、L142 重建——需核对是否丢了旧 API，若重建需把 getAppConfig 也带上）。
3. 修复后自检路径：激活机构版 → 重启 → `CONFIG.edition==='clinic'` → getEditionTag()==='离线机构版' → 顶部显示【用户管理】+【处方查阅】，移动端 btn2 保持改密。
- 注意：**不要改 HTML/CSS**（受保护）；按钮显隐是 JS 逻辑，合法。

### 涉及文件
