fix(offline-desktop): Setup 1.0.80 按钮单隐根治——双保险正向兜底+反向applyRuntimePermissions对称修复

根因(1.0.79 仍失败的真实原因, 与自动登录竞态无关):
Permission.applyRuntimePermissions() 只在 isPersonal() 时隐藏 userManageBtn, 完全不动 clinicPrescriptionBtn.
该函数在 Permission.init.then(异步回调) 中触发, 微任务调度相对顺序与 checkLoginStatus 自动登录内的 updateUserDisplay **不确定**:
若 applyRuntimePermissions 在 updateUserDisplay 之后执行, 且此时 Permission._currentEdition()=personal, 就把 updateUserDisplay 已经设为 canManage→block 的 userManageBtn 单独打回 none,
但 clinicPrescriptionBtn 从未被 applyRuntimePermissions 触碰, 保持 block —— 出现【处方查阅】显示/两个按钮都无的诡异不一致.

修复(双保险单一入口正向兜底):
- enforceStandardEditionButtons 新增 __healInstitutionBtns() 唯一落地函数(按 CONFIG.edition/Permission._edition + currentUser.role 计算 canManage/canChangePwd, 显式重置三件套 display+visibility).
- enforce 所有 7 个出口统一调用: 三处豁免 return/mustEnforce=false return/强制正常尾巴/catch 异常尾巴/函数最末尾终极对齐. 任何豁免/提前 return 前都先正向对齐.
- applyRuntimePermissions(shared/permission.js 281-312) 追加 isInstitutional() 对称分支: 机构版时反向显式恢复三件套 display/visibility. 兜底策略正反覆盖.

同步: shared/permission.js → 10 份权限副本全量复制+哈希一致(public/public.electron/cloud_desktop×2/cloud_app.assets/offline_desktop×2/offline_app/site-admin×2).

打包坑(asar缓存复用): 同 outputDir 重打 1.0.79→1.0.80, electron-builder 静默复用旧 asar, 表现为 version 升了但修复标识 ②/⑤ False.
→ 解: 每次重打 Remove-Item -Recurse dist_new 清空输出目录后再 builder.

验证(清空 dist_new 后重打): ①__appConfigReady ②自动登录await ③竞态自愈×2 ④__healInstitutionBtns ⑤机构版正向兜底×2 ⑥1.0.80 全部 True.

已验证: check-interface.bat 6 OK 界面基线一致.

生效方式:
- 离线桌面版: 安装 dist_new\惠康中医-本地 Setup 1.0.80.exe
- 云端各端/离线APP: 推 GitHub 自动部署(permission.js 兜底 + 后续再补云端 enforce 同源兜底)
