# 多用户离线处方同步方案

## Context

用户需求：云端桌面/APP支持多普通用户离线保存处方（含拍照录像），管理员手动触发同步后按时间戳合并各用户离线处方，云端分配统一编号，媒体文件不上云端但管理员可查看文件列表。当前系统已实现离线存储、自动同步、云端统一编号、管理员查看权限，但缺少管理员手动同步入口和媒体文件元数据管理。

## 需求分析

| 需求 | 当前状态 | 需要修改 |
|------|----------|----------|
| 多用户离线保存处方 | ✅ 已实现（LocalDB + SyncEngine） | 无 |
| 离线编号LOCAL-YYMMDD-序号 | ✅ 已实现 | 无 |
| 联网后云端统一编号 | ✅ 已实现（generatePrescriptionNo） | 无 |
| 管理员查看所有用户处方 | ✅ 已实现（后端filter逻辑） | 无 |
| 媒体文件不上云端 | ✅ 已实现（仅本地保存） | 无 |
| 管理员手动触发同步 | ❌ 缺少 | 添加同步按钮 |
| 管理员推送时保留原始创建者 | ❌ 后端会覆盖createdBy | 修改后端 |
| 管理员查看媒体文件列表 | ❌ 缺少 | 添加mediaFiles元数据 |

## 验证方法

### 后端验证
1. 普通用户保存处方，记录prescriptionNo和createdBy
2. 管理员POST同一条处方（带mediaFiles），验证prescriptionNo不变、createdBy保持原用户

### 管理员同步验证
1. 用户A离线保存处方（synced=0）
2. 管理员登录，打开处方查阅，点击"同步离线数据"
3. 验证推送的处方createdBy为用户A（不是管理员）

### 媒体文件验证
1. 普通用户保存处方（含拍照/录像）
2. 验证云端处方记录包含mediaFiles字段
3. 管理员看到媒体文件指示器（📷🎥(N)）
4. 管理员点击查看：共享电脑可直接查看，非共享显示文件列表+提示

## 设计决策

1. **方案C（元数据上云+内容本地）**：管理员能看到文件清单，共享电脑直接查看，非共享明确提示联系人。复杂度最低。
2. **不修改SyncEngine.run()模式检查**：管理员通过独立函数绕过，职责分离。
3. **用POST更新而非新增PUT**：复用现有去重逻辑，向后兼容。
