# 优化手动打包文件 - 提高打包速度 & 删除多余打包文件

## Context

项目包含多个端（云端桌面、云端APP、3个离线桌面、3个离线APP），经过多次迭代打包后积累了大量旧打包产物和多余文件，总计约 **2GB** 可释放空间。同时各端打包脚本缺少清理步骤，导致旧文件残留影响打包速度。

## 一、删除多余文件（释放约2GB）

### 1. 旧打包产物（dist目录）
以下dist目录均为旧的Electron打包产物，每次 `npm run build` 会重新生成，可安全删除：

| `dist/`（根目录，含完整项目副本+node_modules） | 423.9 MB |
| `cloud_project/cloud_desktop/dist/` | 416.1 MB |
| `offline_project/db-dingzhi/dist/` | 398.3 MB |
| `offline_project/db-geren/dist/` | 398.3 MB |

- `cloud_project/tcm-prescription-system/` (25.9 MB) — 被.gitignore排除的origin仓库clone，无实际用途

### 3. 多余依赖

## 二、优化打包脚本

### 1. 桌面端 build.bat（4个文件，统一添加清理步骤）

修改以下4个文件，在打包前自动清理旧dist：
- `cloud_project/cloud_desktop/build.bat`
- `offline_project/db-bendi/build.bat`
- `offline_project/db-dingzhi/build.bat`
- `offline_project/db-geren/build.bat`

修改模式：在 `[2/3] 执行打包...` 之前插入清理步骤：
```bat
echo [2/4] 清理旧打包产物...
if exist "dist" rmdir /s /q "dist"
echo [OK] 旧产物已清理
echo.
echo [3/4] 执行打包...
```
总步骤数从 3 改为 4，最后的 `[3/3]` 改为 `[4/4]`。

### 2. Android build-app.bat（3个离线APP，添加clean步骤）

修改以下3个文件，在assembleRelease前添加clean：
- `offline_project/db-bendi/build-app.bat`
- `offline_project/db-dingzhi/build-app.bat`
- `offline_project/db-shouji/build-app.bat`

修改模式：在 `call gradlew.bat assembleRelease` 前添加：
```bat
echo [2.5/4] 清理构建缓存...
call gradlew.bat clean --no-daemon
if errorlevel 1 (
    echo [WARN] clean失败，继续增量构建
) else (
    echo [OK] 缓存已清理
)
echo.
```

注意：云端APP的 `cloud_project/打包.bat` 已有clean步骤，无需修改。

## 三、验证

1. 确认删除后磁盘空间释放（约2GB）
2. 确认各端 build.bat 脚本能正常执行：
   - 桌面端：`npm run build` 能正常生成dist
   - APP端：`gradlew.bat assembleRelease` 能正常生成APK
3. 确认 .gitignore 已排除所有打包产物（已确认无需修改）

## 四、各端生效方式

本次修改仅涉及本地文件清理和打包脚本优化，不影响已部署的应用：
- 云端网页版：无影响（未修改网页代码）
- 云端桌面版：下次打包时使用优化后的build.bat
- 云端APP：无影响（未修改cloud_app/打包.bat）
- 离线桌面版×3：下次打包时使用优化后的build.bat
- 离线APP×3：下次打包时使用优化后的build-app.bat（添加了clean步骤）
