## 四、全套完整需求明细（所有功能落地标准）

### （一）定制版专属规则（version-custom）

1. 根目录存在 `config.txt`，存储诊所名称、医师展示中文名。
2. 软件【基础设置】页面内诊所名称、医师姓名输入框固定只读，界面无法编辑。
3. 修改方式：记事本打开 `config.txt` 手动编辑，刷新 / 重启程序自动读取更新。
4. 页面其余工具栏、按钮、处方编辑功能全部正常操作，无额外限制。
5. 沿用项目原有处方编号逻辑，不套用云端日期流水号规则。

### （二）用户账号体系（三版本通用，底层英文 ID + 页面中文展示）

1. 数据库 / 缓存唯一标识：登录账号、用户 ID 使用拼音 / 英文，杜绝中文路径、缓存乱码。
2. 单独存储「医师中文姓名」字段，所有页面、处方头部、统计报表、打印单据统一展示中文真名。
3. 两种角色严格区分：管理员（admin）、普通用户（normal）。

**管理员权限：**

- 顶部工具栏显示【用户管理】入口
- 用户管理页面功能：新增账号、删除账号、修改全部账号登录密码
- 处方数据权限：查看系统内所有用户全部历史处方
- 统计面板：展示全诊所全局汇总处方数量、统计数据

**普通用户权限：**

- 顶部工具栏自动隐藏【用户管理】菜单，无法访问用户管理页面
- 仅开放「修改本人登录密码」功能，不能操作其他账号
- 处方数据权限：仅查看当前登录医师本人开具的处方
- 统计面板仅展示个人处方统计数据

**越权拦截：** 通过地址强制跳转管理员页面会弹窗提示无权限，自动返回首页。

### （三）云端版核心强制规范（version-cloud，解决多设备数据 / 编号错乱）

1. **数据存储原则**：所有处方、用户、统计业务数据永久只持久化在云端服务端；客户端仅做页面展示、本地临时缓存，不落地保存正式业务处方数据。
2. **处方编号固定规则（服务端统一管控）：**
   - 格式：`YYMMDD + 01~99`（两位年份 + 两位月份 + 两位日期 + 两位流水号）
   - 编号生成权仅在云端服务端，客户端只接收、展示编号，本地不生成、不自增、不修改编号
   - 每日零点流水号自动重置从 01 开始，多设备并发新建处方加锁控制，保证编号全局唯一、无重复、顺序不乱
   - 以服务端系统时间为准，不受客户端电脑本地时间影响
   - 处方列表按编号升序渲染，天然匹配处方开具先后顺序
3. **页面加载提速（本地缓存机制）：**
   - 缓存隔离规则：缓存键拼接 `用户ID + 角色`，不同账号、设备缓存完全独立，不会串数据
   - 渲染逻辑：页面打开优先读取本地缓存秒速渲染，后台异步静默请求云端最新数据覆盖页面
   - 区分刷新动作：页面自动刷新走缓存静默同步；手动点击刷新按钮强制拉取云端最新数据；退出登录自动清空当前账号全部缓存
4. **离线管控规则：**
   - 网络断开、无法连接云端接口时，仅允许查看已缓存历史处方
   - 禁止新建处方、保存处方，弹窗提示网络异常
   - 从根源避免离线造数导致编号、数据错乱
5. **多设备登录协同：** 任意设备提交处方实时同步云端，其他设备刷新后自动拉取最新数据，全终端内容统一。

### （四）图片保存统一规范（三版本、网页 / 桌面端通用）

1. 点击处方保存按钮，自动生成处方截图图片。
2. 图片内打印展示的门诊编号，强制与当前处方编号完全一致。
3. 增加前置校验：无有效处方编号时，拦截图片保存并弹窗提示。
4. Electron 桌面端存储规则：
   - 图片统一自动存放在程序安装目录 `/img_save` 文件夹
   - 程序自动按「年-月」新建子文件夹分类存储，无需手动创建目录
5. 文件命名规范：`时间戳 + 处方编号`，避免重名覆盖。

### （五）全局页面通用优化（全版本统一）

1. 摒弃整页刷新，全部改为局部刷新；刷新后自动保留当前搜索条件、分页页码、页面状态，不会重置页面。
2. 定制版页面刷新同步重读 `config.txt` 配置文件；云端版刷新同步同步云端数据。
3. 全局异常兜底处理：文件缺失、文件夹权限不足、网络断开、配置文件损坏、空处方编号、越权操作全部增加友好弹窗提示，程序不崩溃卡死。

### （六）Electron 桌面端专属配置

1. 登录页面独立为固定尺寸小弹窗，禁止拖拽缩放、禁止最大化。
2. 登录校验成功后自动关闭登录小窗口，拉起主业务窗口。
3. 网页端、桌面端共用同一套业务、权限、编号、存图逻辑，功能完全一致。
4. 支持分别打包本地版、云端版、定制版三套独立桌面安装包。

### （七）Git 仓库管理 + 云端一键部署标准化流程

**分支划分（固定不变）：**

- `main`：生产稳定主分支，线上一键部署唯一源码，禁止直接在该分支写代码
- `dev-cloud`：云端版迭代开发分支
- `dev-local`：本地版开发分支
- `dev-custom`：定制版开发分支

**标准开发提交流程：**

1. 切换对应版本开发分支 → 增量修改代码 → 本地完整自测
2. `git add` → `git commit`（清晰备注修改内容）→ `git push` 推送远程开发分支
3. 功能全部验证无误后，将开发分支合并至 `main` 主分支并推送远程
4. 一键部署：自动化部署工具绑定 `main` 分支，点击一键部署自动拉取代码、打包、更新云端服务
5. 故障回滚机制：线上出现严重 BUG，可通过 Git 回退至上一稳定提交版本，重新一键部署快速恢复业务
