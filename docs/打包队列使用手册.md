# 打包队列使用手册

> 适用范围：惠康中医平台管理后台「📦 打包队列」及 `POST /api/build-queue`
> 最后更新：2026-11-17

## 1. 功能定位

打包队列解决的是「谁要打哪个包、打到哪一步、产物在哪」的协作问题，**不负责执行打包本身**。

- Cloudflare Pages 只能运行 Functions，无法调用本地 Electron/Android 打包脚本。
- 队列负责：任务登记、状态流转、产物信息回执（SHA-256、体积、下载地址）。
- 实际打包由本地打包机上的脚本完成：打包机轮询 `claim` 认领任务，打包完成后 `update` 回执。

## 2. 角色与权限

| 角色 | 能力 | 认证方式 |
| --- | --- | --- |
| 平台管理员 | 查看队列、新建任务、取消、重试 | 后台登录后的 Bearer token |
| 打包机（本地脚本） | 认领任务、回执结果 | 请求头 `X-Build-Token`，命中环境变量 `BUILD_QUEUE_TOKEN` |

> 打包机令牌只能调用 `claim` / `update`，不能新建、取消或读取整个队列。

## 3. 后台页面操作

入口：管理后台顶部「📦 打包队列」，或直接访问 `/admin/build-queue.html`。

1. **新建任务**：选择打包目标、填写版本号（如 `2026.11.17-1`）和备注，点击「加入队列」。
2. **查看状态**：页面每 20 秒自动刷新；页面切到后台时暂停轮询，回到前台立即刷新一次。
3. **取消任务**：排队中/打包中的任务可点「取消」。
4. **重试任务**：失败/已取消的任务可点「重试」，重新回到排队状态。
5. **查看产物**：成功任务显示 SHA-256 前 12 位、文件体积和下载链接（若回执时提供）。
6. **最后更新时间**：列表标题旁显示「更新于 HH:mm:ss」，悬停可看完整日期。

打包目标取值：

| 值 | 含义 |
| --- | --- |
| `cloud-desktop` | 云桌面 |
| `cloud-app` | 云 APP |
| `offline-desktop` | 离线桌面 |
| `offline-app` | 离线 APP |
| `cloud-web` | 云端网页 |
| `hot-update` | 热更新包 |

## 4. 状态机

```
queued ──claim──> building ──update(success)──> success
   │                  │
   │                  └──update(failed)───> failed ──retry──> queued
   └──cancel──> cancelled ──retry──> queued
                  building ──cancel──> cancelled
```

- `queued`：已入队，等待打包机认领
- `building`：打包机已认领，正在打包
- `success`：打包成功，产物信息已回执
- `failed`：打包失败，`message` 为失败原因
- `cancelled`：管理员取消

## 5. API 参考

**地址**：`POST https://tcm-prescription-system.pages.dev/api/build-queue`

**请求头**：

```
Content-Type: application/json
Authorization: Bearer <平台管理员 token>      # 管理动作
# 或
X-Build-Token: <BUILD_QUEUE_TOKEN>            # 打包机 claim/update
```

### 5.1 查看队列（管理员）

```json
{ "action": "list" }
```

响应：

```json
{
  "success": true,
  "tasks": [ /* 按 createdAt 倒序，最多 100 条 */ ],
  "stats": { "queued": 1, "building": 1, "success": 3, "failed": 0, "cancelled": 0, "total": 5 },
  "targets": { "cloud-desktop": "云桌面", "...": "..." }
}
```

### 5.2 新建任务（管理员）

```json
{
  "action": "create",
  "target": "cloud-desktop",
  "version": "2026.11.17-1",
  "note": "修复打印模板"
}
```

响应：`{ "success": true, "task": { ... } }`

约束：

- `target` 必须是上表六种之一
- `version` ≤ 40 字符，`note` ≤ 200 字符
- 同目标 + 同版本已有 `queued`/`building` 任务时返回 `409`，防止重复排队

### 5.3 认领任务（打包机）

```json
{ "action": "claim" }
```

响应：

```json
{ "success": true, "task": { "id": "bt_xxx", "status": "building", ... } }
```

队列为空时：

```json
{ "success": true, "task": null, "message": "队列为空" }
```

认领规则：取最早创建的 `queued` 任务，置为 `building` 并写入 `startedAt`、`claimedBy`。

> KV 最终一致，`claim` 不是强并发锁。请只运行一个打包机代理，或自行在代理侧串行处理。

### 5.4 回执结果（打包机）

成功：

```json
{
  "action": "update",
  "taskId": "bt_xxx",
  "status": "success",
  "version": "2026.11.17-1",
  "sha256": "<64 位十六进制>",
  "sizeBytes": 12345678,
  "downloadUrl": "https://example.com/pkg.exe",
  "message": "打包完成"
}
```

失败：

```json
{
  "action": "update",
  "taskId": "bt_xxx",
  "status": "failed",
  "message": "electron-builder 退出码 1：签名失败"
}
```

约束：

- `status` 仅接受 `success` / `failed`
- `sha256` 必须是 64 位十六进制（可省略）
- `sizeBytes` 必须是非负整数（可省略）
- `downloadUrl` ≤ 500 字符；建议使用对象存储/静态站 HTTPS 地址
- 已取消的任务不能回执（返回 `409`）

### 5.5 取消 / 重试（管理员）

```json
{ "action": "cancel", "taskId": "bt_xxx" }
{ "action": "retry",  "taskId": "bt_xxx" }
```

- `cancel`：仅 `queued` / `building` 可取消
- `retry`：仅 `failed` / `cancelled` 可重试，重试后清空上一次产物信息

### 5.6 错误码

| HTTP | 含义 |
| --- | --- |
| 400 | 参数缺失或非法（目标、状态、sha256、sizeBytes 等） |
| 401 | 未授权：缺少/无效管理员 token，或打包机令牌错误 |
| 404 | 任务不存在（或已过 30 天 TTL） |
| 409 | 重复入队、状态不允许该操作 |
| 500 | 服务端异常 |
| 503 | 存储不可用 |

## 6. 环境变量配置

在 Cloudflare Pages 项目 → Settings → Environment variables 添加：

| 变量名 | 说明 |
| --- | --- |
| `BUILD_QUEUE_TOKEN` | 打包机专用长随机字符串（建议 32 位以上） |

注意：

- 未配置 `BUILD_QUEUE_TOKEN` 时，`claim/update` 只能使用管理员 token。
- 令牌只保存在打包机本地环境变量中，**不要写入仓库、前端页面或聊天记录**。
- 轮换令牌：更新 Pages 环境变量并重新部署，同时更新打包机环境变量。

生成随机令牌（PowerShell）：

```powershell
$bytes = [byte[]](1..32 | ForEach-Object { Get-Random -Maximum 256 })
[Convert]::ToBase64String($bytes)
```

## 7. 打包机接入示例（PowerShell）

```powershell
$Api   = 'https://tcm-prescription-system.pages.dev/api/build-queue'
$Token = $env:BUILD_QUEUE_TOKEN
$Headers = @{
  'X-Build-Token' = $Token
  'Content-Type'  = 'application/json'
}

while ($true) {
  # 1) 认领任务
  $claim = Invoke-RestMethod -Method Post -Uri $Api -Headers $Headers `
            -Body '{"action":"claim"}'

  if ($null -eq $claim.task) {
    Start-Sleep -Seconds 30
    continue
  }

  $task = $claim.task
  Write-Host "认领任务 $($task.id) -> $($task.target) $($task.version)"

  try {
    # 2) 执行实际打包（按 target 调用你的打包脚本）
    #    & .\build-cloud-desktop.ps1 -Version $task.version

    $artifact = '.\dist\setup.exe'
    $sha  = (Get-FileHash $artifact -Algorithm SHA256).Hash.ToLower()
    $size = (Get-Item $artifact).Length

    # 3) 上传产物到可访问的下载地址（示例：省略上传步骤）
    $downloadUrl = "https://example.com/releases/$($task.version)/setup.exe"

    # 4) 回执成功
    $body = @{
      action      = 'update'
      taskId      = $task.id
      status      = 'success'
      version     = $task.version
      sha256      = $sha
      sizeBytes   = $size
      downloadUrl = $downloadUrl
      message     = '打包完成'
    } | ConvertTo-Json

    Invoke-RestMethod -Method Post -Uri $Api -Headers $Headers -Body $body | Out-Null
    Write-Host "回执成功 $($task.id)"
  } catch {
    # 5) 回执失败
    $body = @{
      action  = 'update'
      taskId  = $task.id
      status  = 'failed'
      message = $_.Exception.Message
    } | ConvertTo-Json

    Invoke-RestMethod -Method Post -Uri $Api -Headers $Headers -Body $body | Out-Null
    Write-Host "回执失败 $($task.id)：$($_.Exception.Message)"
  }
}
```

Node.js 伪代码：

```js
const API = 'https://tcm-prescription-system.pages.dev/api/build-queue';
const headers = { 'Content-Type': 'application/json', 'X-Build-Token': process.env.BUILD_QUEUE_TOKEN };

async function call(body) {
  const res = await fetch(API, { method: 'POST', headers, body: JSON.stringify(body) });
  const data = await res.json();
  if (!data.success) throw new Error(data.error);
  return data;
}

const { task } = await call({ action: 'claim' });
if (task) {
  try {
    const artifact = await build(task);              // 你的打包函数
    await call({
      action: 'update', taskId: task.id, status: 'success',
      version: task.version, sha256: artifact.sha256,
      sizeBytes: artifact.size, downloadUrl: artifact.url, message: '打包完成'
    });
  } catch (e) {
    await call({ action: 'update', taskId: task.id, status: 'failed', message: e.message });
  }
}
```

## 8. 任务字段说明

| 字段 | 说明 |
| --- | --- |
| `id` | 任务号，格式 `bt_<时间戳36进制>_<随机4位>` |
| `target` | 打包目标（六种之一） |
| `version` | 版本号 |
| `note` | 入队备注 |
| `status` | `queued` / `building` / `success` / `failed` / `cancelled` |
| `createdAt` | 入队时间（毫秒时间戳） |
| `createdBy` | 入队管理员用户名 |
| `startedAt` | 认领时间 |
| `finishedAt` | 完成/失败/取消时间 |
| `claimedBy` | 认领者（`build-agent` 或管理员用户名） |
| `sha256` | 产物 SHA-256（64 位小写十六进制） |
| `sizeBytes` | 产物字节数 |
| `downloadUrl` | 产物下载地址 |
| `message` | 失败原因或回执说明 |

## 9. 数据与保留策略

- 存储：Cloudflare KV，键名 `build_task:{id}`
- 保留：**30 天**（写入时设置 TTL，过期自动清理）
- 列表：返回最新 100 条任务
- 版本/备注/消息长度上限：40 / 200 / 300 字符
- 队列统计基于最近 100 条任务计算

## 10. 常见问题

**Q1：页面提示「未登录」或「鉴权失败」？**
先在 `/admin/index.html` 登录平台管理员。令牌保存在 `sessionStorage`，换标签页打开会丢失，需重新登录。

**Q2：入队返回 409？**
同目标 + 同版本已有排队中/打包中任务。等它完成，或先取消旧任务。

**Q3：`claim` 一直返回 `task: null`？**
队列为空；或任务都已是 `building/success/failed/cancelled`。可在后台查看统计与状态。

**Q4：`claim` 返回 401？**
`X-Build-Token` 与 Pages 环境变量 `BUILD_QUEUE_TOKEN` 不一致，或环境变量未配置且未携带管理员 token。

**Q5：回执 409「任务已取消，不能回执」？**
任务在打包期间被管理员取消。丢弃本次产物即可，不要重试回执。

**Q6：产物下载链接打不开？**
`downloadUrl` 只是回执字段，队列不托管文件。请把产物上传到对象存储/静态站后再回执，并确认链接可公开访问或带有效期签名。

**Q7：能否自动触发打包？**
不能。Pages 无法访问本地构建环境；需要打包机主动轮询。若后续接入 CI（如 GitHub Actions），同样通过 `claim/update` 协议对接即可。

## 11. 安全须知

1. `BUILD_QUEUE_TOKEN` 只放打包机环境变量与 Pages 环境变量，禁止提交到 Git。
2. 管理 token 只保存在浏览器 `sessionStorage`，页面刷新/关闭即失效。
3. `downloadUrl` 建议使用 HTTPS，并避免在链接中携带数据库密码等敏感参数。
4. 打包机应只运行可信脚本；`claim` 到的任务字段仅作参数，不要直接拼接执行未校验的命令。
5. 发现令牌泄露：立即在 Pages 更新 `BUILD_QUEUE_TOKEN` 并重新部署，旧令牌随即失效。

## 12. 排障速查

```powershell
# 查看队列（管理员 token）
$h = @{ Authorization = 'Bearer <admin-token>'; 'Content-Type' = 'application/json' }
Invoke-RestMethod -Method Post -Uri 'https://tcm-prescription-system.pages.dev/api/build-queue' `
  -Headers $h -Body '{"action":"list"}'

# 认领（打包机 token）
$h = @{ 'X-Build-Token' = $env:BUILD_QUEUE_TOKEN; 'Content-Type' = 'application/json' }
Invoke-RestMethod -Method Post -Uri 'https://tcm-prescription-system.pages.dev/api/build-queue' `
  -Headers $h -Body '{"action":"claim"}'
```

浏览器开发者工具 → Network → 筛选 `build-queue`，可直接看到每次请求与响应；Cloudflare Pages → Functions 日志可查看 5xx 异常。
