# 离线激活文件生成 · 客服操作手册

> **版本**：v1.0
> **更新日期**：2026-07-25
> **适用范围**：惠康中医诊所管理系统（云端桌面版 + 离线3端桌面版）
> **适用场景**：客户机器无法联网激活时，客服代为生成离线激活文件

---

## 一、什么时候使用本流程？

当客户**无法联网激活**软件时，客服可按本流程为客户生成"离线激活文件"，客户导入该文件即可完成正式激活。

**适用条件**（同时满足）：
- 客户机器无法连接互联网
- 客户已有激活码（格式：`BNZC-XXXX-XXXX-XXXX-XXXX`）
- 客户能从激活窗口复制到"机器 ID"（32 位字母数字）

---

## 二、客服前置准备（一次性配置）

### 1. 申请客服密钥

向系统管理员申请 `LICENSE_EXPORT_SECRET`（客服专用密钥，32 位随机串）。**这是客服独立调用接口的凭证，无需登录管理后台**。

### 2. 安装调用工具（任选其一）

| 工具 | 适合人群 | 获取方式 |
|---|---|---|
| **curl**（推荐） | 略懂命令行的客服 | Windows 10/11 已内置，打开 PowerShell 即可用 |
| Postman | 不熟悉命令行的客服 | https://www.postman.com/downloads/ |
| 在线工具 | 临时使用 | https://reqbin.com/curl |

### 3. 记录接口地址

```
POST https://tcm-prescription-system.pages.dev/api/license/export-license
```

## 三、完整操作流程

### 步骤 1：客户向客服提供 3 项信息

客户从激活窗口复制以下信息发给客服：

| 信息 | 示例 | 客户如何获取 |
|---|---|---|
| **机器 ID** | `a1b2c3d4e5f678901234567890abcdef` | 激活窗口"本机机器 ID"框 → 点击"复制"按钮 |
| **诊所名称** | 本能堂中医诊所 | 激活窗口"诊所名称"输入框（需与激活码绑定的诊所一致） |
| **激活码** | `BNZC-ABCD-EFGH-JKLM-NPQR` | 客服此前通过销售流程发给客户的激活码 |

### 步骤 2：客服调用接口生成 license 文件

#### 方式 A：使用 curl（推荐）

打开 PowerShell（Windows 开始菜单 → 输入 `powershell` → 回车），复制粘贴以下命令（替换方括号内容）：

```powershell
curl -X POST https://tcm-prescription-system.pages.dev/api/license/export-license `
  -H "Content-Type: application/json" `
  -H "X-Export-Secret: [客服密钥]" `
  -d '{\"code\":\"[激活码]\",\"machineId\":\"[机器ID]\",\"clinicName\":\"[诊所名称]\"}'
```

**示例**（替换为实际值）：

```powershell
curl -X POST https://tcm-prescription-system.pages.dev/api/license/export-license `
  -H "Content-Type: application/json" `
  -H "X-Export-Secret: abc123xyz456def789ghi012jkl345mn" `
  -d '{\"code\":\"BNZC-ABCD-EFGH-JKLM-NPQR\",\"machineId\":\"a1b2c3d4e5f678901234567890abcdef\",\"clinicName\":\"本能堂中医诊所\"}'
```

#### 方式 B：使用 Postman

1. 新建请求：
   - Method：`POST`
   - URL：`https://tcm-prescription-system.pages.dev/api/license/export-license`
2. Headers 标签页：
   - `Content-Type`：`application/json`
   - `X-Export-Secret`：`[客服密钥]`
3. Body 标签页 → 选 `raw` → 选 `JSON`：
   ```json
   {
     "code": "BNZC-ABCD-EFGH-JKLM-NPQR",
     "machineId": "a1b2c3d4e5f678901234567890abcdef",
     "clinicName": "本能堂中医诊所"
   }
   ```
4. 点击 **Send** 发送请求

### 步骤 3：客服解析返回结果

#### 成功响应示例

```json
{
  "success": true,
  "license": "eyJ1c2VyIjoi5byg5LiJIiwidHlwZSI6InBybyIsImlzc3VlZEF0IjoiMjAy...",
  "licenseInfo": {
    "user": "张三",
    "type": "pro",
    "issuedAt": "2026-07-25T10:30:00.000Z",
    "expiresAt": "2027-12-31T00:00:00.000Z",
    "maxPrescriptions": 0,
    "features": ["backup", "sync", "multi-device", "priority-support"],
    "clinicName": "本能堂中医诊所",
    "licenseBinding": "clinic+user+machine",
    "maxDevices": 1,
    "devicesCount": 1
  },
  "fileName": "license_本能堂中医诊所_a1b2c3d4_20260725.dat",
  "message": "license 已生成，请将文件安全发送给客户..."
}
```

**关键字段**：
- `license`：base64 编码的 license 内容（**这是核心内容，客户需要它**）
- `licenseInfo`：license 元信息（用于客服核对，不发客户）
- `fileName`：建议保存的文件名

#### 失败响应示例

```json
{
  "success": false,
  "error": "激活码已过期"
}
```

### 步骤 4：客服保存 license 文件

将返回的 `license` 字段内容保存为 `.dat` 文件。

#### 方式 A：PowerShell 自动保存（推荐）

在原 curl 命令后追加解析与保存逻辑：

```powershell
$response = curl -X POST https://tcm-prescription-system.pages.dev/api/license/export-license `
  -H "Content-Type: application/json" `
  -H "X-Export-Secret: abc123xyz456def789ghi012jkl345mn" `
  -d '{\"code\":\"BNZC-ABCD-EFGH-JKLM-NPQR\",\"machineId\":\"a1b2c3d4e5f678901234567890abcdef\",\"clinicName\":\"本能堂中医诊所\"}'

$json = $response | ConvertFrom-Json
$json.license | Out-File -FilePath "$env:USERPROFILE\Desktop\license_本能堂_a1b2c3d4.dat" -Encoding utf8 -NoNewline
Write-Host "✅ 文件已保存到桌面：license_本能堂_a1b2c3d4.dat"
```

#### 方式 B：手动复制保存

1. 从响应中复制 `license` 字段的内容（`eyJ1c2Vy...` 那一长串）
2. 桌面新建文本文档，重命名为 `license.dat`（注意修改扩展名）
3. 用记事本打开，粘贴 license 内容，保存

**重要**：保存时**不要包含引号、空格、换行**，文件内容就是纯 base64 字符串。

### 步骤 5：客服将文件发给客户

通过微信/QQ/邮件将 `license.dat` 文件发送给客户。

### 步骤 6：客户导入文件完成激活

引导客户操作：
1. 在激活窗口找到黄色按钮"📁 导入离线激活文件"
2. 点击按钮 → 选择客服发的 `.dat` 文件
3. 弹窗显示 license 信息（用户/版本/诊所/到期），核对诊所名是否正确
4. 点击"确定"
5. 软件提示"✅ 激活成功"，自动重启
6. 重启后即为正式授权版本

## 四、常见错误处理

| 错误信息 | 原因 | 解决方法 |
|---|---|---|
| `需要平台管理员权限或有效的 LICENSE_EXPORT_SECRET` | 密钥错误或未设置 | 联系管理员确认 `LICENSE_EXPORT_SECRET` 环境变量已配置且密钥正确 |
| `激活码不存在` | 激活码错误或未生成 | 在管理后台 `/api/license/list` 查询激活码状态 |
| `激活码已被禁用` | 激活码 status=disabled | 在管理后台 `/api/license/status` 启用激活码 |
| `激活码已过期` | record.expiresAt 已过 | 在管理后台 `/api/license/extend` 延期 |
| `此激活码已绑定诊所，必须提供 clinicName` | 未传诊所名 | 让客户提供激活窗口显示的诊所名称 |
| `诊所名与激活码绑定的诊所不一致` | 诊所名错误 | 让客户从激活窗口复制完整诊所名，注意全角字符 |
| `machineId 长度需在 8-128 之间` | 机器ID错误 | 让客户重新复制机器ID（32 位字母数字） |
| `激活码格式错误，应为 BNZC-XXXX-XXXX-XXXX-XXXX` | 激活码格式错误 | 确认激活码完整无空格 |
| 客户导入时提示"激活文件与本机不匹配" | 文件不是为该机器生成的 | 确认客户提供的机器ID与生成时使用的一致 |
| 客户导入时提示"授权文件写入权限不足" | 客户安装在 Program Files | 让客户右键"以管理员身份运行"软件 |

## 五、注意事项

### 5.1 安全要求
- **客服密钥严禁泄露**：密钥可生成 license，等同于授权凭证，仅限本人使用
- **每个 license 仅对一台机器有效**：machineId 不同则无法激活
- **激活码会被标记为已使用**：调用接口后激活码 status 变为 `used`，无法二次激活（同机重激活除外）
- **操作有日志记录**：每次调用都会记录操作者、IP、时间，可追溯

### 5.2 客户信息核对要点
- **机器 ID 必须是 32 位字母数字**（如 `a1b2c3d4...`），不是"本能堂"等中文名
- **诊所名必须与激活码绑定的一致**，包括标点符号、全角半角
- **激活码格式**：`BNZC-XXXX-XXXX-XXXX-XXXX`，去除易混淆字符（无 I/O/0/1）

### 5.3 同机重激活
- 同一机器ID 对同一激活码重复调用接口：**允许**，不会消耗新设备配额
- 适用于客户重装系统后重新激活的场景

### 5.4 换机激活
- 客户换新机器时，新机器ID 不同于旧机器
- 若激活码设备配额已满，接口会**自动解绑最旧设备**允许换机
- 换机激活后，旧机器的 license **不会立即失效**，但下次联网验证时会检测到被解绑

### 5.5 文件传输建议
- 微信发送 `.dat` 文件可能被拦截，建议改后缀为 `.txt` 发送，客户接收后改回 `.dat`
- 或压缩为 `.zip` 后发送
- 邮件附件无此限制

```
┌─────────────────────────────────────────┐
│  客户提供 → 机器ID + 诊所名 + 激活码      │
└────────────────┬────────────────────────┘
                 ↓
┌─────────────────────────────────────────┐
│  PowerShell 执行 curl 命令              │

└────────────────┬────────────────────────┘
                 ↓
       success: true ?
       ├─ 是 → 复制 license 字段
       │       保存为 license.dat 文件

       │
       └─ 否 → 查错误信息表
              对症处理后重试
```

## 七、附录

### 7.1 接口请求参数说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `code` | string | 是 | 激活码，格式 `BNZC-XXXX-XXXX-XXXX-XXXX` |
| `machineId` | string | 是 | 客户机器 ID，32 位字母数字，长度 8-128 |
| `clinicName` | string | 条件必填 | 诊所名称；激活码已绑定诊所时必填，不含 `\|`，长度 ≤100 |
| `user` | string | 否 | 用户名，覆盖激活码上的 user |

### 7.2 接口响应字段说明

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | boolean | 是否成功 |
| `license` | string | base64 编码的 license 内容（保存为 .dat 文件） |
| `licenseInfo.user` | string | 用户名 |
| `licenseInfo.type` | string | 版本类型：trial / personal / pro |
| `licenseInfo.issuedAt` | string | 签发时间 ISO |
| `licenseInfo.expiresAt` | string | 到期时间 ISO |
| `licenseInfo.maxPrescriptions` | number | 处方上限（0=无限） |
| `licenseInfo.features` | string[] | 功能列表 |
| `licenseInfo.clinicName` | string | 绑定的诊所名 |
| `licenseInfo.licenseBinding` | string | 绑定模式 |
| `licenseInfo.maxDevices` | number | 最大设备数 |
| `licenseInfo.devicesCount` | number | 已绑定设备数 |
| `fileName` | string | 建议保存的文件名 |
| `message` | string | 提示信息 |
| `error` | string | 失败时的错误信息 |

### 7.3 鉴权方式

接口支持两种鉴权方式（任选其一）：

| 方式 | 请求头 | 适用场景 |
|---|---|---|
| 客服密钥（推荐） | `X-Export-Secret: [密钥]` | 客服日常使用，无需登录管理后台 |
| 管理员 token | `Authorization: Bearer [token]` | 管理员临时使用 |
