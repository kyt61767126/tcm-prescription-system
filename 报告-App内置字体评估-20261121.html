App 内置字体方案评估报告

惠康中医 · 处方签打印字体 · 2026-11-21 · 仅评估，未改动任何代码

一句话结论：内置字体解决的是「不同手机打印结果不一样」，解决不了「App 与桌面一模一样」。当前「惠康堂中医诊所 / 处方笺」与桌面不同，根因不是字号、也不是内置字体的缺陷，而是两款不同字体：桌面命中 Windows 楷体（KaiTi），App 命中内置的霞鹜文楷（HKKai）。

内置字体这份投入值得保留（换来跨机型稳定），但要达到与桌面逐笔一致，必须让桌面也使用同一份字体文件；否则只能做到"接近"。

一、现状与实测数据

1. 字体来源

实测缺失示例：䗪（䗪虫）、蟅、萹（萹蓄）、蛴螬 等药名用字，以及人名常用字 珺 燚 龑 垚 喆 昇 堃 赟 婳 骉 犇。桌面有系统大字库，这些字照常显示；App 会局部换字体、字宽也可能不同。

4. 打印链路里的时间点（风险项）

App 打印是「隐藏 WebView 渲染 → 抓成 300dpi 位图 → 送系统打印」。抓图时机是 onPageFinished + 400ms 固定延时，没有等待字体加载完成（document.fonts.ready）。冷启动首打、低端机解析 1.5MB woff2 较慢时，存在「字体还没生效就抓图」的偶发风险：表现为某一次打印的标题回退成系统字体（字形/字宽变化）。这条与本次反馈无关，但属于内置字体方案必须补的安全垫。

二、使用 App 自带字体的优点

优点说明
跨机型输出稳定不依赖手机是否装了楷体/宋体。华为、小米、vivo 的默认衬线字体各不相同，不内置就必然"一机一样"。
尺寸可精确校准内置字体是固定文件，汉字宽度与桌面实测差 0.8%，西文/数字已用 size-adjust 校准（数字 89.5%、字母 85%），剂量、年龄、编号不再偏大。
离线可用字体随 APK 分发，断网、纯本地处方照常打印，不依赖 CDN。
授权合规霞鹜文楷、思源宋体均为 OFL-1.1，可商用、可随包分发（许可文本已随包）；而 Windows 楷体/宋体属微软字体，不能打包分发。
与网页/桌面同源同一份 public/fonts 三端共用，后续若统一字体源，改动集中在一处。

三、使用 App 自带字体的缺点与风险

缺点 / 风险说明
仍然与桌面字体不同霞鹜文楷 ≠ Windows 楷体（中易楷体）。同为楷体，但起笔收笔、横竖比例、结体不同，22pt 加粗后差异被放大——就是你现在看到的「惠康堂中医诊所 / 处方笺」不一致。内置字体只统一了安卓各机型，没有统一桌面。
生僻字回退GBK 覆盖仅 34%：患者姓名（珺、垚、喆、昇、堃、赟等）或药名（䗪虫、萹蓄等）会局部回退系统字体，出现"一行里两种字体"。
体积 +2.98MB（20%）安装包变大，弱网更新更慢；且字体在 assets 内，不能热更，每次调整字体都要整包重打、重新分发。
标题伪加粗内置楷体只有 Regular 一个字重，font-weight:bold 由系统"描边加粗"，笔画会发糊；桌面系统楷体同样无粗体，两者伪粗算法还不完全一致，进一步放大差异。
抓图抢跑风险见上文 400ms 固定延时；字体未就绪时会打印出系统字体，属偶发性故障，且目前无日志可查。
维护成本字体文件、子集范围、西文度量、字号联动，任一处改动都要三端同步验证（网页/桌面/云端 App/离线 App）。

四、可选方案对比

方案做法与桌面一致性代价
A. 保持现状App 用内置字体，桌面用系统字体不同（当前问题）无
B. 三端统一用内置字体打印模板把 HKKai/HKSong 排到系统字体之前，桌面/网页/App 全用同一份字体文件逐笔一致（同一字体文件 + 同一 Chromium 渲染）桌面打印观感由「系统楷体/宋体」变为「霞鹜文楷/思源宋体」；屏幕显示可保持不变
C. App 换更接近系统楷体的开源字体用文鼎 PL 楷体 / FandolKai 等替换 HKKai，桌面不动接近，但不保证逐笔一致需新字体文件 + 子集化 + 重新校准西文度量 + 重打；仍有观感差异
D. 不内置字体回归安卓系统字体差异最大，且各机型互不相同省 3MB，但打印结果不可控（不建议）

五、建议

  1. 保留内置字体（方案 D 不可取）——它保证了安卓各机型打印结果稳定，这是目前唯一可控的基础。
  2. 若要「与桌面逐笔一致」，走 方案 B：仅打印模板把内置字体排到系统字体之前，桌面日常屏幕显示不变。这是唯一能做到真正一致的路径。
  3. 无论选 A 还是 B，补齐两处安全垫：
    • 抓图前等待 document.fonts.ready（替代 400ms 固定延时），并在日志里打印字体是否就绪；
    • 字体子集从 GB2312 扩到 GBK 常用字（至少覆盖人名与中药名），缺字时写日志，避免"悄悄换字体"。
  4. 若坚持桌面保持 Windows 楷体，则只能接受「接近但不完全一致」（方案 C），且需要先取到可商用楷体文件再评估观感，属于新增工作量与不确定结果。
