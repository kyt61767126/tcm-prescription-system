## 第一章 软件概述

### 1.1 软件简介

惠康中医诊所管理系统（以下简称"本系统"或"本软件"）是一款专为基层中医诊所、中医门诊部以及个体中医医师设计开发的 clinic 信息化管理软件。系统以中医处方录入与打印为核心，围绕中医诊疗日常工作流程，提供患者信息管理、处方开具、药品管理、验方维护、病例检索、数据统计、用户权限管理以及问诊视频录制与舌诊拍照等辅助功能，旨在帮助中医诊疗机构提高工作效率、规范诊疗行为、保存诊疗数据并实现数据资产的本地化沉淀。

本系统为离线机构定制版本，采用本地化数据存储方案，所有患者处方、药品信息、验方数据均保存在用户本机或局域网内，不依赖外部云服务器，能够满足中医诊所对数据隐私性、独立性和离线可用性的需求。系统同时提供 Windows 桌面端与 Android 移动端两个发行版本，桌面端基于 Electron 框架构建，移动端基于 Capacitor 框架打包，两端共享同一套核心业务逻辑，确保数据结构一致、操作体验统一。

本系统由惠康中医团队独立研发，软件版本号为 V1.0.0，内部构建标识为 2026-07-29-v1。软件以诊所日常开方业务为主线，融合了中医辨证论治思想，支持以"证"选"方"的快捷开方模式，同时支持复诊直调、验方调用、药品简码检索等中医特色功能，充分贴合中医师的实际操作习惯。

### 1.2 开发背景

随着中医药事业的振兴发展，基层中医诊所数量持续增长，中医诊疗活动具有处方个性化强、复诊频次高、药材组合灵活等特点。传统的纸质处方书写方式存在书写不规范、字迹难以辨认、历史处方检索困难、统计数据分析不便等问题，难以满足现代中医诊所的精细化管理需求。

市面上的医疗信息化产品多以西医诊疗流程为核心，对中医辨证论治、中药处方、验方传承等特色业务支持不足；同时大量云端 SaaS 产品需要持续的联网环境和年费订阅，对网络条件不佳、预算有限或对数据隐私要求较高的基层诊所并不友好。

基于上述背景，惠康中医团队结合自身多年中医临床与诊所运营经验，研发了本套离线化的中医诊所管理系统。系统坚持"轻量、离线、易用、安全"的设计理念，无需联网即可独立运行，数据完全保存在本机，既保障了诊所数据资产的安全可控，又降低了诊所的信息化使用门槛与运营成本。

### 1.3 主要功能

本系统主要提供以下功能模块：

1. **处方录入与打印**：支持患者基本信息、病史症状、诊断、药品明细、剂数、诊疗费的完整录入，实时生成处方预览，支持纵向与横向两种打印格式，自动生成处方编号。

2. **历史处方管理**：按患者姓名实时检索历史处方，支持处方查看、编辑、删除，提供回收站功能以防止误删除，管理员可查阅全诊所处方。

3. **药品管理**：维护中药药品库，记录药品简码、名称、单位、单价等信息，支持药品新增、编辑、删除、搜索、批量导入与导出。

4. **验方设置**：维护常用经验方，记录方名、功效、主治、组成药物，支持通过验方快速生成处方，并提供辨证选方快捷入口。

5. **病例管理**：以病例视角汇总患者所有就诊处方，支持按姓名与日期范围检索病例，便于回顾患者完整诊疗历程。

6. **数据统计**：提供就诊人数、初复诊、复诊率、就诊趋势、病种分布、常用药材 Top10、患者就诊列表、月度收支报表等多维度统计分析，支持报表导出。

7. **用户管理**：管理员可新增、编辑、删除用户，分配普通用户或管理员角色，查看各用户开具的处方，修改密码。

8. **录像与拍照**：支持调用摄像头录制问诊视频与拍摄舌诊照片，文件自动关联到最近保存的处方患者，便于建立完整的患者影像档案。

9. **数据备份与恢复**：一键备份全量数据为本地文件，支持从备份文件恢复数据，支持清空全部数据。

10. **系统安全**：登录认证、会话超时、密码哈希加密、远程调试拦截、DevTools 拦截等多重安全防护机制。

### 1.4 技术特点

本系统在技术架构与工程实现方面具有以下特点：

1. **跨平台桌面框架**：桌面端基于 Electron 35.0.0 框架构建，使用 HTML5、CSS3、原生 JavaScript 作为前端开发语言，复用 Web 技术栈，便于快速迭代与跨平台移植。Electron 主进程通过 contextBridge 安全暴露原生 API，渲染进程在 contextIsolation 启用、nodeIntegration 禁用的安全模式下运行。

2. **离线本地存储**：采用 IndexedDB 作为主要数据存储引擎，数据库命名为 PrescriptionDB，包含 prescriptions（处方）与 settings（设置）两个对象仓库。同时使用 localStorage 作为辅助存储与降级方案，确保在 IndexedDB 不可用环境下仍可正常运行。视频与备份文件通过 Electron 文件系统 API 写入本地磁盘。

3. **统一数据适配层**：通过 db-adapter.js 模块封装 IndexedDB、localStorage、Electron 文件系统与云端 API 的统一 CRUD 接口，支持渐进增强与错误降级，业务层无需关心底层存储细节。

4. **共享业务核心模块**：将登录认证（auth-core.js）、处方业务（prescription-core.js）、权限管理（permission.js）、药品字典（medicine-dict.js）、打印工具（print-utils.js）、性能工具（performance-utils.js）、患者档案（patient-archive.js）、安全防护（security-guard.js）等公共逻辑抽取为独立模块，桌面端与移动端共享，消除重复代码。

5. **密码安全加密**：登录密码采用 PBKDF2 算法进行哈希存储，兼容历史 SHA-256 与明文格式，登录时自动升级为 PBKDF2 格式。Electron 桌面端优先使用 Windows DPAPI（通过 safeStorage 接口）进行系统级加密，绑定用户与机器，即使源码与密文泄露也无法解密。

6. **会话管理**：登录会话设置 8 小时超时，超时后需重新登录；APP 端启动时主动清除所有登录态，确保每次打开应用都必须手动登录，防止设备借阅导致的数据泄露。

7. **安全防护机制**：主进程拦截 `--inspect`、`--remote-debugging-port` 等远程调试启动参数，防止通过 Chrome DevTools 远程连接绕过前端安全校验；渲染进程拦截 F12 等开发者工具快捷键；通过 security-guard.js 模块对关键 API 调用进行登录态校验，防止绕过登录直接调用业务接口。

8. **移动端 Capacitor 打包**：移动端基于 Capacitor 框架将 Web 资源打包为 Android 原生应用，复用桌面端核心业务模块，通过 Cordova 插件调用摄像头、文件系统等原生能力，提供接近原生的使用体验。

9. **按需加载**：第三方库（如 xlsx）采用按需加载策略，首次使用 Excel 导入功能时才动态加载 vendor/xlsx.full.min.js，减少首屏加载时间，未放置该库时仅影响 Excel 导入功能，其他功能不受影响。

10. **审计日志**：关键业务操作（如处方保存）记录审计日志，便于追溯操作行为。

### 1.5 软件适用场景

本系统适用于以下场景：

1. **基层中医诊所**：单医师或多医师的小型中医诊所，需要规范处方书写、保存诊疗数据、统计业务数据。
2. **中医门诊部**：拥有多名中医师的中医门诊部，需要按医师统计工作量、查阅全院处方。
3. **个体中医师**：独立执业的中医师，需要轻量化的处方管理工具，无需复杂的医院信息系统。
4. **中医馆与国医堂**：中医药文化体验馆、国医堂等场所，需要展示中医处方规范化管理。
5. **带教与传承**：中医师带教场景，通过验方设置保存老师经验方，便于学生调用学习。
6. **远程问诊辅助**：通过录像与拍照功能记录问诊过程与舌象，为远程会诊提供资料。

### 1.6 与同类软件的差异化优势

相比市面上的医疗信息化产品，本系统具有以下差异化优势：

1. **纯离线运行**：无需联网，数据完全本地化，满足数据隐私与断网可用需求。
2. **中医特色鲜明**：原生支持辨证选方、验方调用、复诊直调、中药简码检索等中医特色功能，而非简单照搬西医流程。
3. **轻量易用**：单文件部署（便携版），无需安装数据库，无需配置服务器，开箱即用。
4. **跨端协同**：桌面端与移动端共享核心业务逻辑，数据结构一致，可灵活选择使用场景。
5. **数据可控**：所有数据保存在用户本机，用户完全掌控数据资产，无厂商锁定风险。
6. **成本可控**：一次购买永久使用，无年费订阅，无云端存储费用，适合预算有限的基层诊所。
7. **安全加固**：多重安全防护机制（远程调试拦截、DevTools 拦截、密码加密、会话超时等），防止数据泄露与篡改。
8. **影像档案**：内置录像与拍照功能，建立患者问诊视频与舌诊照片档案，辅助辨证论治与医疗纠纷证据保全。

## 第二章 软件安装

### 2.1 桌面版安装

#### 2.1.1 NSIS 安装包安装

NSIS 安装包为标准的 Windows 安装程序，适用于固定办公电脑的常规安装场景。安装步骤如下：

1. 获取安装包文件"惠康中医-LJ-Setup-1.0.0.exe"，将安装包拷贝至目标电脑任意目录。
2. 双击安装包文件启动安装向导。若系统弹出"用户账户控制"对话框，询问是否允许该应用对设备进行更改，请点击"是"以继续。
3. 安装向导启动后，进入欢迎界面，点击"下一步"。
4. 进入"选择安装位置"界面，默认安装路径为"C:\Program Files\惠康中医-LJ"。如需更改，可点击"浏览"按钮选择其他目录，或直接在路径输入框中输入目标路径。建议保持默认路径或选择非系统盘目录以便数据备份。
5. 点击"下一步"进入"选择附加任务"界面，可勾选是否创建桌面快捷方式、是否创建开始菜单快捷方式。默认两项均勾选。
6. 点击"安装"开始复制文件，安装过程中会显示进度条。安装完成后，进入完成界面，勾选"运行 惠康中医-LJ"可立即启动软件。
7. 点击"完成"退出安装向导。

安装完成后，系统会在开始菜单的"惠康中医"程序组下创建"惠康中医-LJ"快捷方式，并在桌面创建同名快捷方式图标。双击快捷方式即可启动软件。

NSIS 安装包支持每机器安装（perMachine），即一次安装可供本机所有用户使用。安装包内含 afterPack.js 脚本与 installer.nsh 自定义脚本，对安装文件进行安全加固（如 asarmor 防反编译保护）。

#### 2.1.2 便携版安装

便携版（portable）为单文件可执行程序"惠康中医-LJ-1.0.0.exe"，适用于 U 盘携带、多机临时使用或不愿在系统中写入注册表的场景。使用步骤如下：

1. 获取便携版可执行文件，拷贝至任意可写目录（如 D:\惠康中医\、U 盘根目录等）。
2. 双击 exe 文件即可启动软件，无需安装。
3. 软件运行时会在 exe 同级目录自动创建 data 子目录用于保存数据文件（包括备份文件、视频文件等）。如该目录不可写，则自动回退到系统 userData 目录。

便携版与安装版功能完全一致，区别仅在于数据存储位置与是否在系统中注册。便携版卸载时直接删除 exe 文件及同级 data 目录即可。

#### 2.1.3 首次启动配置

首次启动软件时，系统会自动执行以下初始化操作：

1. 读取 exe 同级目录或安装目录下的 config.json 配置文件，加载诊所名称、默认医师姓名、版本类型等基础配置。
2. 初始化 IndexedDB 数据库 PrescriptionDB，创建 prescriptions 与 settings 对象仓库。
3. 加载默认用户列表（来自 config.json 的 users 字段），如配置文件未提供则使用内置默认用户。
4. 显示登录界面，等待用户登录。

#### 2.1.4 安装常见问题

**问题一：安装时提示"文件被占用"或"无法写入"**

原因：之前安装的旧版本软件仍在运行，或相关文件被其他程序占用。
解决：1) 关闭正在运行的旧版本软件；2) 通过任务管理器结束所有"惠康中医"相关进程；3) 重启电脑后重新安装。

**问题二：安装后被杀毒软件拦截或删除**

原因：部分杀毒软件（如 360、火绒、电脑管家等）可能误报本软件为风险程序，因为软件包含 asarmor 防反编译保护与远程调试拦截等安全机制。
解决：1) 在杀毒软件中将本软件加入白名单或信任区；2) 安装前临时关闭杀毒软件实时防护；3) 从官方渠道重新下载安装包确保完整性。

**问题三：启动后白屏或闪退**

原因：可能为系统缺少必要运行库、显卡驱动不兼容、或用户数据目录权限不足。
解决：1) 更新显卡驱动至最新版本；2) 以管理员身份运行软件；3) 删除用户数据目录（ userData 目录下的 persist:tcm-prescription-dingzhi 文件夹）后重新启动；4) 联系技术支持。

**问题四：便携版无法保存数据**

原因：便携版 exe 所在目录不可写（如位于只读光盘、受保护的系统目录等）。
解决：将便携版 exe 拷贝至可写目录（如 D 盘根目录、桌面等）后重新运行，系统会自动在该目录创建 data 子目录保存数据。

**问题五：双击 exe 无反应**

原因：可能为系统资源不足、软件正在后台初始化、或 exe 文件损坏。
解决：1) 等待 30 秒后再次尝试；2) 通过任务管理器查看是否有相关进程；3) 重新下载安装包；4) 右键以管理员身份运行。

### 2.2 APP 版安装

APP 版本安装包为 Android 应用程序包（.apk 文件），安装步骤如下：

1. 将 apk 文件传输至 Android 手机，可通过微信、QQ、数据线、U 盘等方式传输。
2. 在手机文件管理器中找到 apk 文件，点击安装。
3. 首次安装时，系统会弹出"允许安装来自此来源的应用"提示，请在系统设置中开启对应权限，然后返回继续安装。
4. 安装完成后，点击"打开"启动应用，或在桌面找到"惠康中医"应用图标点击启动。
5. 首次启动应用时，系统会请求摄像头权限（用于录像与拍照功能），请点击"允许"以启用完整功能。

APP 版本启动时会主动清除所有登录态（包括 isLoggedIn、currentUser、user_login_data 等），确保每次打开应用都需要手动登录，提升数据安全性。APP 端数据保存在应用私有目录，卸载应用会同步清除所有数据，请卸载前务必做好数据备份。

### 2.3 卸载说明

### 3.2 管理员登录

管理员账号拥有系统的全部权限，包括用户管理、处方查阅、修改密码、开机自启设置等。管理员登录步骤如下：

1. 启动软件，进入登录界面。
2. 在"用户"输入框中输入管理员用户名（默认管理员账号由 config.json 配置文件提供，通常为 admin）。
3. 在"密码"输入框中输入管理员密码。密码区分大小写。
4. 如希望下次登录时本机自动记住用户名，勾选"记住用户"复选框。
5. 点击"确定"按钮或按 Enter 键提交登录。

登录验证流程：

1. 系统从 config.json 与本地用户存储中读取用户列表。
2. 查找匹配的用户名，如未找到则提示"用户名或密码错误"。
3. 对输入密码进行哈希计算，与存储的密码哈希值比对。系统支持 PBKDF2、SHA-256 与明文三种格式，登录成功后自动将旧格式（SHA-256/明文）升级为 PBKDF2 格式存储。
4. 验证通过后，记录登录态（currentUser、isLoggedIn、loginData）到 localStorage，并启动 8 小时会话计时。
5. 隐藏登录界面，显示主工作界面。
6. 顶部标签栏根据用户角色显示对应功能按钮：管理员可见"用户管理"、"修改密码"、"处方查阅"按钮。

1. 启动软件，进入登录界面。
2. 输入普通用户用户名与密码。
3. 点击"确定"提交登录。

普通用户登录成功后，主界面顶部标签栏不显示"用户管理"、"处方查阅"按钮，"修改密码"按钮对所有登录用户可见。普通用户仅能查看与编辑自己开具的处方历史，无法查阅其他用户的处方。

### 3.4 记住用户名功能

为提升登录便捷性，本系统提供"记住用户名"功能，登录成功后将用户名保存到本地，下次登录时可通过下拉列表快速选择，免去重复输入。功能说明如下：

1. **启用方式**：登录前勾选"记住用户"复选框，登录成功后系统自动将当前用户名加入记住用户列表。
2. **下拉选择**：下次启动软件进入登录界面时，用户名输入框右侧会显示下拉箭头按钮。点击按钮展开历史用户名列表，点击列表中的用户名即可自动填入输入框。
3. **存储位置**：记住的用户名列表保存在 localStorage 中，键名遵循 auth: 命名空间。
4. **管理方式**：记住用户名列表由系统自动维护，重复登录同一用户名不会产生重复条目。如需清除所有记住的用户名，可清除浏览器缓存或重置应用数据。
5. **安全说明**：记住用户名功能仅保存用户名，不保存密码。每次登录仍需手动输入密码，确保账号安全。

### 3.5 密码安全说明

本系统高度重视用户密码安全，采用多层防护机制：

1. **密码哈希存储**：用户密码不以明文形式保存，而是通过 PBKDF2 算法进行哈希后存储。PBKDF2 使用 PASSWORD_SALT 作为基础盐，并通过 masterKey 派生盐进一步增强安全性，使每个安装的盐值不同。系统兼容历史 SHA-256 与明文格式，登录时自动升级为 PBKDF2 格式。

2. **运行时密钥派生**：在浏览器环境中，密码哈希盐基于运行时环境特征（hostname、navigator.language）派生，使攻击者仅查看源码无法直接获得实际加密密钥，降低纯源码攻击效果。

3. **safeStorage 系统级加密**：Electron 桌面端优先使用 Windows DPAPI（通过 Electron safeStorage 接口）进行系统级加密，密钥绑定 Windows 用户与机器。攻击者即使获取源码与密文，也无法在其他机器上解密。在浏览器或 WebView 中此能力不可用时，自动降级到 XOR 加密方案。

4. **密码自动升级**：用户登录时，若检测到密码仍为旧格式（SHA-256 或明文），系统自动使用 PBKDF2 重新哈希并保存，无需用户主动操作，渐进式提升整体密码安全等级。

5. **会话超时**：登录会话设置 8 小时（28800000 毫秒）超时，超过 8 小时未操作会话失效，需重新登录。

6. **APP 端登录态清除**：APP 端每次启动时主动清除所有登录态相关数据，确保每次打开应用都必须手动登录，防止设备借阅或遗失后的数据泄露。

7. **密码框防自动填充**：密码输入框设置 autocomplete="new-password" 属性，防止浏览器自动填充历史保存的密码，避免密码泄露风险。

8. **登录态校验**：关键业务 API（如保存处方）在执行前校验登录态，若检测到未登录状态直接拒绝调用并提示"请先登录"，防止绕过登录界面直接调用业务接口。

## 第四章 基础设置

### 4.1 诊所信息设置

诊所信息用于处方打印时的诊所名称显示，是软件运行的基础配置项。设置步骤如下：

1. 登录系统后，点击顶部标签栏的"【基础设置】"按钮，或按 F1 快捷键，弹出"F1 基础设置"对话框。
2. 在"诊所名称"输入框中输入诊所名称，如"惠康中医诊所"。该名称将显示在处方预览纸顶部以及打印输出中。
3. 诊所名称支持中文、英文、数字及特殊字符，建议长度不超过 20 个字符以保证打印效果。
4. 点击"保存"按钮保存设置，或点击"取消"放弃修改。

诊所名称保存后立即生效，处方预览区与所有新开具的处方打印件均使用新名称。已保存的历史处方中嵌入的诊所名称不变。

### 4.2 医师信息设置

医师信息用于处方录入时的默认医师姓名填充，避免每次开方重复输入。设置步骤如下：

1. 打开"基础设置"对话框（F1）。
2. 在"医师姓名"输入框中输入默认医师姓名，如"张医生"。该姓名将作为新处方的默认医师。
3. 在实际开方时，医师姓名也可在处方录入界面的"医师"输入框中临时修改，不影响默认设置。
4. 点击"保存"按钮保存设置。

医师姓名保存后，新建处方时"医师"输入框自动填入该默认值。如诊所拥有多位医师，建议为每位医师创建独立用户账号，登录后系统自动以当前登录用户的姓名作为默认医师。

### 4.3 处方编号设置

本系统的处方编号采用"日期+序号"的自动生成规则，确保编号唯一且具有可追溯性。编号格式为 YYMMDD + 两位序号，例如 26080301 表示 2026 年 8 月 3 日的第 1 张处方。

编号生成逻辑：

1. 获取当前保存操作的时间戳，解析为 YYMMDD 格式的日期串（如 260803）。
2. 读取本地存储的 global_max_serial 字段中当日存储的最大序号。
3. 序号加 1，不足两位前置补 0（如 1 → 01）。
4. 拼接完整编号（YYMMDD + 两位序号），如 26080301。
5. 将当日最新序号回写至 global_max_serial 字段持久保存。

处方编号在保存处方时自动生成，无需用户手动输入。处方录入界面的"门诊"输入框默认为只读，保存后显示生成的编号。系统维护 global_max_serial 全局最大序号，确保编号单调递增，即使删除处方也不会复用已生成的编号。

### 4.4 打印模板设置

本系统提供纵向与横向两种处方打印模板，分别适配不同规格的处方笺纸张：

1. **纵向打印**：标准 A5 纵向处方笺，适合大多数诊所使用。处方内容自上而下排列，包括诊所名称、处方标题、患者信息、病史症状、诊断、药品列表、剂数、用法、医师签名等。点击左侧工具栏"纵向打印"按钮或按 F8 快捷键触发。
2. **横向打印**：横向处方笺，适合需要更宽书写空间或特殊打印纸张的场景。内容布局与纵向一致，但整体方向旋转 90 度。点击左侧工具栏"横向打印"按钮触发。

打印模板内容动态生成，根据当前处方录入界面的内容实时渲染。打印前请确认打印机已正确连接并设置为默认打印机，纸张尺寸与打印模板匹配。打印输出包含完整的处方信息，符合《处方管理办法》对中医处方的格式要求。

### 4.5 自动备份设置

本系统提供离线自动备份机制，定期将处方数据备份到本地文件，防止数据意外丢失。备份相关说明：

1. **备份触发**：系统在处方保存等关键操作后自动触发增量备份，将最新的处方列表写入本地存储。
2. **备份位置**：备份文件保存在 exe 同级目录或系统 userData 目录下的指定文件夹中，文件名包含时间戳以便区分。
3. **数据完整性**：备份文件采用 JSON 格式存储，并计算 HMAC 校验值，恢复时自动校验完整性，防止备份文件被篡改或损坏。
4. **手动备份**：除自动备份外，用户可在"数据统计"模块中点击"一键备份"按钮手动导出全量数据备份文件，建议定期将备份文件拷贝至其他存储介质（如 U 盘、网盘）以实现异地备份。
5. **数据恢复**：在"数据统计"模块中点击"恢复数据"按钮，选择历史备份文件即可将数据恢复至备份时的状态。恢复操作会覆盖当前数据，请谨慎操作。
6. **开机自动启动**：管理员用户可在"基础设置"对话框中勾选"开机自动启动"选项，使系统在电脑开机时自动启动，确保数据备份机制持续运行。

### 4.6 其他设置项说明

基础设置对话框中还包含以下设置项：

1. **诊疗费**：默认诊疗费金额（元），新建处方时自动填入该值。可根据诊所定价策略调整，如普通门诊 10 元、专家门诊 50 元等。该值仅为默认值，开方时可在处方录入界面临时修改。
2. **默认剂数**：默认处方剂数，新建处方时自动填入。中医汤剂常用 7 剂（一周量），慢性病调理可用 14 剂或 30 剂，急性病可用 3 剂或 5 剂。可根据诊所主流病种调整默认值。
3. **开机自动启动**（仅管理员可见）：勾选后系统在电脑开机时自动启动。此功能通过写入 Windows 注册表实现，仅管理员角色可见该选项。适用于诊所前台电脑需要全天候运行软件的场景。

设置项保存逻辑：

- 所有设置项保存在 IndexedDB 的 settings 仓库与 localStorage 中，键名遵循统一命名规范。
- 设置项保存后立即生效，无需重启软件。
- 设置项与用户账号关联，每个用户的设置独立保存（部分全局设置如诊所名称除外）。
- 清除浏览器缓存或重置应用数据会丢失设置项，建议通过"一键备份"功能定期备份设置。

#### 5.0.2 处方录入典型工作流

一个完整的处方录入工作流如下：

1. 登录系统，进入主工作界面。
2. 在"姓名"输入框中输入患者姓名：
   - 若为复诊患者，系统自动匹配历史患者，下拉列表显示候选，点击候选可自动填充性别、年龄、电话、住址等信息。
   - 若为新患者，手动录入各项信息。
3. 在"病史症状"文本框中输入主诉与病史。
4. 在"诊断"输入框中输入中医诊断（建议包含病名与证型）。
5. 调整"剂数"为所需剂数（默认 7 剂）。
6. 录入药品：
   - 方式一：逐味在"简码"或"药物"列输入，通过下拉候选选择药品。
   - 方式二：按 Alt+1 辨证选方，从验方库调用对应方剂，自动填充药品。
   - 方式三：按 Alt+9 复诊直调，加载该患者最近处方药品。
7. 调整各药品剂量，系统实时计算金额。
8. 如需要，修改"诊疗费"金额。
9. 检查处方预览区，确认内容无误。
10. 按 F9 或点击"保存"按钮保存处方。
11. 按 F8 或点击"纵向打印"/"横向打印"按钮打印处方。
12. 如需录像或拍照，点击移动端快捷操作栏对应按钮。

整个流程一气呵成，熟练医师开一张处方通常仅需 1-3 分钟。

### 5.1 患者信息录入

患者信息录入区位于左侧面板顶部，包含门诊号、性别、日期、姓名、年龄、电话、统计号、住址等字段。各字段说明如下：

1. **门诊号**：处方编号，只读字段，保存处方时自动生成（格式 YYMMDD+序号），新建处方时为空。
2. **性别**：下拉选择框，可选"男"或"女"。点击该字段可循环切换性别，选择后自动标记为手动修改状态。系统提供智能性别匹配功能，根据患者姓名自动推断性别（基于姓名用字特征），用户可手动覆盖。
3. **日期**：就诊日期，只读字段，默认为当天日期，格式 YYYY-MM-DD。保存处方时自动写入。
4. **姓名**：患者姓名输入框，必填字段。输入时支持拼音码检索历史患者：在输入框中键入字符时，系统实时检索历史处方中匹配的患者姓名，以下拉列表形式显示候选。点击候选姓名可自动填充患者姓名、性别、年龄、电话、住址等历史信息，加速复诊录入。聚焦该输入框时，右侧历史处方列表会自动显示该患者的就诊记录。
5. **年龄**：患者年龄输入框，接受数字或文字（如"3月"、"成人"等）。
6. **电话**：患者联系电话输入框，方便后续联系与复诊通知。
7. **统计号**：患者在本诊所的统计编号，只读字段，由系统自动维护，用于数据统计模块的患者去重与就诊次数计算。
8. **住址**：患者住址输入框，记录患者居住地信息。

录入患者信息时，建议先输入姓名。若历史处方中已存在该患者，系统会自动填充其他字段，用户可在自动填充的基础上修改。若为新患者，则需手动录入各项信息。

### 5.2 诊断信息录入

诊断信息录入区位于患者信息区下方，包含病史症状、诊断、剂数、医师四个字段：

1. **病史症状**：多行文本输入框，标签栏分为"病史症状"与"修改病史"两个标签页。在"病史症状"标签下输入患者主诉、现病史、既往史等内容。输入时处方预览区实时同步更新。该字段支持自由文本输入，建议使用中医术语规范描述，如"恶寒发热，无汗，头痛身疼，舌淡红苔薄白，脉浮紧"。
2. **诊断**：单行文本输入框，输入中医诊断或西医诊断，如"感冒（风寒证）"或"急性上呼吸道感染"。输入时处方预览区实时同步。建议填写中医病名与证型，便于后续病种统计。
3. **剂数**：数字输入框，默认值为 7，表示处方剂数。可直接修改数字或通过键盘输入。剂数变化时处方预览与金额计算实时更新。常见取值为 3、5、7、14 等。
4. **医师**：单行文本输入框，默认填入基础设置中的默认医师姓名或当前登录用户姓名。可临时修改为实际开方医师姓名。修改不影响默认设置。

诊断信息录入时，处方预览区的对应字段会实时显示输入内容，方便用户直观确认录入结果。

### 5.3 药品选择与录入

药品录入区位于左侧面板底部，以表格形式呈现，列标题依次为：#（序号）、简码、药物、数量、单位、单价、合计、删。表格默认显示 15 行空白行，供用户逐味录入药品。录入方式有两种：

#### 5.3.1 通过简码检索录入

1. 在"简码"列输入药品简码（药品拼音首字母组合，如"黄芪"的简码为"hq"）。
2. 输入时系统实时检索药品库，在下方显示匹配的候选药品下拉列表。
3. 使用上下方向键在候选列表中切换，按 Enter 键或点击候选项选中。
4. 选中后，系统自动填充该行的药物名称、单位、单价字段，焦点跳转至"数量"列。

#### 5.3.2 通过药名检索录入

1. 在"药物"列直接输入药品名称（支持中文或拼音）。
2. 输入时系统实时检索药品库，显示匹配候选下拉列表。
3. 选中候选药品后，自动填充单位、单价字段。

#### 5.3.3 手动录入

对于药品库中不存在的新药，可直接在"药物"列手动输入药名，并手动填写单位、单价字段。手动录入的药品不会自动加入药品库，如需长期使用建议在药品管理模块中添加。

药品表格支持多行同时录入，每行一味药。如默认 15 行不足以容纳全部药品，系统会自动追加新行。删除某味药可点击该行"删"列的删除按钮。

### 5.4 剂量与用法设置

每味药品的剂量（数量）与单位是处方的重要组成部分：

1. **数量**：药品剂量，数字输入框。在选中药品后焦点自动跳转至此列。输入数字后，系统自动计算该行合计金额（数量 × 单价），并更新处方总金额。常用单位为克（g），剂量通常为 3-30 之间。
2. **单位**：药品计量单位，默认为"g"（克）。点击单位单元格可修改为其他单位（如 ml、片、粒等），但中药处方绝大多数情况使用"g"。
3. **用法**：处方用法说明显示在处方预览区底部，默认为"水煎服，日一剂，早晚分服"。该用法为中医汤剂通用服法，无需用户手动修改。

剂量与剂数的关系：每味药品的"合计"= 单价 × 数量（即每剂该药品的金额）；处方"药费"= 所有药品合计之和（即每剂总药费）；处方"总计"= 药费 × 剂数 + 诊疗费。

### 5.5 处方预览

处方预览区位于主界面中间面板，以模拟纸质处方笺的形式实时显示当前录入内容。预览纸布局自上而下：

1. **诊所名称**：顶部居中显示，字体加粗放大，由基础设置中的诊所名称提供。
2. **处方标题**："处 方 笺"字样，居中显示。
3. **患者信息行**：横向排列，包括姓名、性别、年龄、科别（默认"中医内科"）、门诊号、日期。
4. **病史症状区**：显示病史症状文本，下方有横线分隔。
5. **诊断区**：显示诊断文本，下方有横线分隔。
6. **药品列表区**：以"RP"标记开头，显示所有药品名称与剂量，按每行 2-3 味药排列。右侧显示剂数（如"7 剂"）。
7. **用法与签名区**：底部显示用法说明（"水煎服，日一剂，早晚分服"），以及"医师:___（签字）"、"配方:___ 复核:___"签名栏。

预览区随录入实时更新，任何字段修改立即反映在预览纸上，所见即所得。预览区底部显示金额信息：每剂金额、药费、诊疗费、总计金额，所有金额保留两位小数。

### 5.6 处方保存

处方录入完成后，需保存到数据库以便后续查询与统计。保存步骤：

1. 确认患者姓名已填写（姓名为必填字段，未填写时保存会被拒绝并提示"请输入患者姓名！"）。
2. 确认至少录入一味有效药品（药品名不为空）。
3. 确认剂数大于 0。
4. 点击左侧工具栏"保存"按钮，或按 F9 快捷键，触发保存操作。

保存流程内部执行步骤：

1. 校验登录状态，未登录则拒绝保存。
2. 校验处方数量限制（试用版本有月度处方数量上限，定制版无限制）。
3. 获取当前时间戳，解析为 YYMMDD 日期串。
4. 生成新的处方编号（YYMMDD + 两位序号）。
5. 采集患者信息、药品表格数据。
6. 使用当前药品库的最新单价重新计算各药品合计与处方总金额（支持修改历史处方时按最新价格结算）。
7. 组装处方记录对象，字段包括：id（时间戳）、prescriptionNo（处方编号）、date（日期）、patientName、patientGender、patientAge、patientPhone、patientAddress、doctorName、medicalHistory、diagnosis、items（药品列表）、doseCount（剂数）、totalAmount（总金额）、registrationFee（诊疗费）、createdAt（生成时间戳）、createdBy（登录用户名）、createdByName（登录用户姓名）。
8. 写入 IndexedDB prescriptions 仓库。
9. 更新内存中的处方历史数组（插入到数组开头）。
10. 记录审计日志。
11. 处方计数加 1（试用版本）。
12. 触发增量备份。
13. 弹出保存成功提示。

保存成功后，处方编号显示在"门诊"输入框中，右侧历史处方列表顶部出现新保存的处方条目。

### 5.7 处方打印

处方保存后可打印输出。打印操作步骤：

1. 完成处方录入并保存（建议先保存再打印，避免打印过程中数据丢失）。
2. 点击左侧工具栏"纵向打印"或"横向打印"按钮，或按 F8 快捷键（默认纵向打印）。
3. 系统调用浏览器打印接口，弹出打印预览对话框。
4. 在打印对话框中选择打印机，设置纸张尺寸（建议 A5 或专用处方笺）、打印方向（与所选打印模式一致）、边距等参数。
5. 点击"打印"按钮输出纸质处方。

打印输出内容包括：诊所名称、处方笺标题、患者完整信息、病史症状、诊断、全部药品明细（药名、剂量、单位）、剂数、用法、医师签名等。打印模板符合中医处方的规范要求，便于药房配药与患者保存。

### 5.8 辨证选方

辨证选方是本系统的中医特色功能，通过"以证选方"的方式快速调用验方生成处方。操作步骤：

1. 按Alt+1 快捷键，或点击顶部标签栏"【验方设置】"后在验方列表中选择，弹出"Alt+1 中医辨证选方"对话框。
2. 对话框列出所有已保存的验方，每条验方显示方名（加粗）、功效、主治信息。
3. 根据患者辨证结果，点击对应的验方条目。
4. 系统自动将所选验方的组成药物填充到处方药品表格中，每味药的名称、剂量、单位、单价、合计自动计算填入。
5. 关闭对话框后，处方预览区与金额计算自动更新。
6. 用户可在自动填充的基础上根据患者具体情况调整剂量、增减药味。

辨证选方功能依赖验方设置模块中维护的验方数据。验方调用时，系统会自动从药品库中查询每味药的最新单价，与验方保存时的剂量组合，计算金额。如验方中某味药在药品库中不存在，单价默认为 0，需用户手动补录。

### 5.9 复诊直调

复诊直调功能用于快速调用患者最近一次就诊的处方，适用于慢性病复诊或效不更方场景。操作步骤：

1. 按 Alt+9 快捷键触发复诊直调。
2. 系统自动加载当前患者（处方录入界面"姓名"字段所示患者）最近一次的就诊处方。
3. 加载的处方药品明细填充到处方药品表格，诊断、剂数等字段同步填充。
4. 用户可在加载基础上调整剂量、增减药味，生成新的复诊处方。
5. 调整完成后，按 F9 保存为新处方。

复诊直调功能极大地简化了复诊开方流程，避免了重复录入相同药品的繁琐操作，特别适合长期随访的慢性病患者管理。

## 第六章 历史处方管理

### 6.1 历史处方列表

历史处方列表位于主界面右侧面板，显示当前登录用户开具的历史处方。列表布局：

1. **列表头部**：标题"处方历史"，右侧显示"刷新"按钮（🔄）与"回收站"按钮（🗑️）。
2. **列表内容**：默认显示最近 15 条处方，每条处方显示患者姓名、处方编号、日期、药品味数、总金额等关键信息。
3. **加载更多**：列表底部显示"加载更多"按钮，点击可加载更早的历史处方。

列表显示规则：

- 普通用户仅能看到自己开具的处方（基于 createdBy 字段过滤）。
- 管理员可看到全部用户的处方（通过"处方查阅"功能，详见 6.4 节）。
- 列表按时间倒序排列，最新处方在最上方。
- 当处方录入界面"姓名"字段聚焦时，列表自动过滤为该患者的历史处方，便于复诊时回顾既往用药。

### 6.2 处方搜索

本系统提供多种处方检索方式：

1. **按患者姓名实时检索**：在处方录入界面"姓名"输入框中输入字符，右侧历史处方列表实时过滤显示该患者的处方。聚焦姓名输入框时，列表自动显示该患者全部历史处方。
2. **历史处方列表内的搜索**：列表支持按姓名、门诊号、诊断等关键字搜索。
3. **病例管理模块搜索**：在"病例管理"对话框中按患者姓名与日期范围搜索（详见第九章）。
4. **处方查阅模块搜索**（管理员）：在"处方查阅"对话框中按姓名、门诊号、诊断关键字及医师筛选（详见 6.4 节）。

历史处方列表的实时检索采用防抖（debounce）技术，输入停止后延迟触发检索，避免频繁刷新影响性能。

### 6.3 处方查看与编辑

历史处方支持查看与编辑操作：

1. **查看处方**：在历史处方列表中点击某条处方，系统加载该处方的完整内容到处方录入界面，包括患者信息、诊断、药品明细等。处方预览区同步显示。用户可查看处方详情，但"门诊号"字段保持只读，显示原处方编号。
2. **编辑处方**：加载历史处方后，可修改任意字段（如调整剂量、增减药味、修改诊断等）。修改后点击"保存"按钮，系统会重新计算金额并保存为新处方（生成新的处方编号与时间戳），原处方保留不变。这种"编辑即另存"的设计保证了处方历史的可追溯性，符合医疗文书的留痕要求。
3. **删除处方**：在历史处方列表中点击某条处方右侧的删除按钮，可将处方移入回收站。删除操作不会立即永久清除数据，可在回收站中恢复（详见 6.4 节）。

加载历史处方时，系统使用当前药品库的最新单价重新计算各药品合计与处方总金额，确保金额计算始终基于最新价格。

### 6.4 处方查阅（管理员）

处方查阅是管理员专属功能，可查阅全诊所所有用户开具的处方，便于业务监管与质量审查。

#### 6.4.1 进入处方查阅

1. 管理员登录后，顶部标签栏显示"【处方查阅】"按钮（绿色背景，与其他按钮区分）。
2. 点击该按钮，弹出"📋 处方查阅"对话框。

#### 6.4.2 界面布局

对话框布局：

1. **筛选区**：顶部显示搜索输入框（placeholder"搜索姓名/门诊号/诊断"）、医师筛选下拉框（选项包括"全部医师"与各医师姓名）、"🔄 刷新"按钮。
2. **统计信息区**：显示符合条件的处方总数等统计信息。
3. **处方列表区**：以列表形式显示处方，每条显示患者姓名、处方编号、日期、医师、药品味数、金额等信息，支持滚动浏览。

#### 6.4.3 操作说明

1. 在搜索框中输入关键字（姓名、门诊号或诊断片段），列表实时过滤显示匹配处方。
2. 点击医师下拉框选择特定医师，列表仅显示该医师开具的处方。
3. 点击"🔄 刷新"按钮重新加载全部处方。
4. 点击某条处方可查看详情。

### 6.5 回收站管理

为防止误删除导致数据丢失，本系统提供处方回收站功能：

1. **进入回收站**：点击历史处方列表头部的"🗑️"按钮，弹出"处方回收站"对话框。
2. **回收站内容**：列表显示已删除的处方，每条显示患者姓名、处方编号、处方日期、删除时间，并提供"恢复"与"彻底删除"两个操作按钮。
3. **恢复处方**：点击"恢复"按钮，将选中的处方从回收站恢复到处方历史列表。恢复操作会清除删除标记，处方重新出现在历史列表中。
4. **彻底删除**：点击"彻底删除"按钮，永久删除该处方，无法恢复。请谨慎操作。
5. **清空回收站**：回收站底部提供"清空回收站"按钮，一键清空所有回收站内容。
6. **保留规则**：回收站最多保留最近 30 天的删除记录，最多 50 条，超出自动清理最早的记录。
7. **权限说明**：回收站按用户隔离，每个用户仅能看到自己删除的处方。

## 第七章 药品管理

### 7.1 药品列表

药品管理模块用于维护本诊所的中药药品库，是处方录入与金额计算的基础数据源。进入药品管理：

1. 点击顶部标签栏"【药品管理】"按钮，或按 F2 快捷键，弹出"F2 药品管理"对话框。
2. 对话框顶部显示搜索框（placeholder"搜索药品"）与"新增药品"、"导出药品"、"导入药品"、"清空药物库"等操作按钮。
3. 下方为药品列表区，以列表形式显示所有药品，每条显示药品简码、名称、单位、单价等信息，支持滚动浏览。
4. 列表支持按简码或名称排序，方便查找。

药品列表加载时从本地存储读取药品数据（localStorage 的 medicines 键或 IndexedDB settings 仓库），加载完成后建立药品名称到药品对象的映射表（buildMedicineMap），供处方录入时的快速检索使用。

### 7.2 药品添加

新增药品步骤：

1. 在药品管理对话框点击"新增药品"按钮，弹出药品编辑表单。
2. 填写药品信息：
   - **简码**：药品拼音首字母组合，如"黄芪"输入"hq"。简码用于处方录入时的快速检索，必填。
   - **名称**：药品标准名称，如"黄芪"。必填。
   - **单位**：默认计量单位，如"g"（克）。中药通常使用"g"。
   - **单价**：药品单价（元/单位），数字格式，如 0.5 表示 0.5 元/克。
   - **分类**（可选）：药品分类，如"解表药"、"补益药"等，便于分类管理。
3. 点击"保存"按钮，新药品添加到药品库，列表实时刷新。

添加药品时系统会自动生成唯一标识，并同步更新药品名称映射表。药品添加后立即可在处方录入中使用。

### 7.3 药品编辑

修改已有药品信息步骤：

1. 在药品列表中找到目标药品，点击该条目的"编辑"按钮（或点击药品名称进入编辑模式）。
2. 弹出药品编辑表单，显示当前药品信息。
3. 修改需要变更的字段（如调整单价、修改简码等）。
4. 点击"保存"按钮保存修改，列表实时刷新。

药品单价修改后，后续新开具的处方将使用新单价计算金额。已保存的历史处方中的单价不变，但加载历史处方时会使用药品库的最新单价重新计算金额（详见 5.3 节）。

### 7.4 药品删除

删除药品步骤：

1. 在药品列表中找到目标药品，点击该条目的"删除"按钮。
2. 系统弹出确认对话框，询问是否确认删除。
3. 点击"确认"删除药品，点击"取消"放弃操作。

删除药品后，该药品不再出现在处方录入的检索候选中。已保存处方中包含该药品的记录不受影响，药品名称与剂量信息仍完整保留在处方数据中。

### 7.5 药品分类

药品分类用于对药品库进行组织管理，便于按类别查找与统计。分类操作：

1. 在新增或编辑药品时，可在"分类"字段填写或选择药品分类。
2. 常见分类包括：解表药、清热药、泻下药、祛风湿药、化湿药、利水渗湿药、温里药、理气药、消食药、驱虫药、止血药、活血化瘀药、化痰止咳平喘药、安神药、平肝息风药、开窍药、补虚药、收涩药、涌吐药、攻毒杀虫止痒药、拔毒化腐生肌药等。
3. 药品列表支持按分类筛选显示。

### 7.6 药品导入导出

为方便药品库的批量维护与迁移，本系统提供药品导入与导出功能：

#### 7.6.1 导出药品

1. 点击"导出药品"按钮，系统将当前药品库导出为文件。
2. 支持的导出格式：Excel（.xlsx，需 xlsx 库支持）、CSV（.csv）、JSON（.json）。
3. 导出文件包含所有药品的完整信息（简码、名称、单位、单价、分类等）。
4. 导出文件可用于数据备份或在其他设备上导入使用。

#### 7.6.2 导入药品

1. 点击"导入药品"按钮，弹出文件选择对话框。
2. 选择药品文件（支持 .csv、.json、.xlsx、.xls 格式）。
3. 系统解析文件内容，弹出"选择导入方式"对话框，提供三种导入模式：
   - **追加（保留现有药品）**：将导入的药品添加到现有药品库末尾，保留所有现有药品。
   - **覆盖（替换现有药品）**：用导入的药品完全替换现有药品库，现有药品全部清除。
   - **合并（同名覆盖，以导入为准）**：对同名药品以导入文件中的信息覆盖现有信息，其他现有药品保留。
4. 选择合适的导入方式后点击对应按钮执行导入。
5. 导入完成后列表刷新，显示新的药品库内容。

导入前请务必备份现有药品库（先导出），以防导入错误导致数据丢失。Excel 导入功能依赖 vendor/xlsx.full.min.js 库，若该库未放置，Excel 导入不可用，请将 Excel 文件另存为 CSV 格式后再导入。

### 7.7 清空药物库

清空药物库功能用于完全清除药品库所有数据：

1. 点击"清空药物库"按钮（红色背景）。
2. 系统弹出确认对话框，警告该操作将删除所有药品数据且不可恢复。
3. 确认后清空药品库。

此操作风险较高，请谨慎使用，操作前务必导出备份。

### 7.8 药品库维护建议

良好的药品库维护是高效开方的基础，建议遵循以下实践：

1. **简码规范**：简码采用药品名称的拼音首字母组合，全小写。如"黄芪"→"hq"、"金银花"→"jyh"、"生地黄"→"sdh"。简码应唯一且易于记忆，避免冲突。
2. **名称规范**：药品名称使用《中华人民共和国药典》标准名称，如"黄芪"而非"北芪"、"当归"而非"秦归"。饮片规格可在名称中体现，如"生白术"、"炒白术"、"酒当归"等。
3. **单价及时更新**：药材市场价格波动较大，建议每季度核查一次药品单价并更新，确保处方金额计算准确。
4. **分类完整**：为每味药填写分类字段，便于按类别管理与统计。常用分类参考《中药学》教材的分类体系。
5. **定期清理**：定期清理不再使用的药品（如已停售、已替换的品种），保持药品库精简高效。
6. **备份习惯**：每次批量修改药品库前先导出备份，操作完成后再次导出，便于回滚。

### 7.9 药品导入文件格式示例

#### 7.9.1 CSV 格式示例

```
简码,名称,单位,单价,分类
hq,黄芪,g,0.50,补虚药
dd,当归,g,0.80,补虚药
cs,陈皮,g,0.20,理气药
f,l,g,0.30,解表药
gz,甘草,g,0.15,补虚药
```

第一行为表头，必须包含简码、名称、单位、单价四个字段（分类可选）。后续每行一味药，字段间用英文逗号分隔。文件编码建议使用 UTF-8 以支持中文。

#### 7.9.2 JSON 格式示例

```json
[
  {"code":"hq","name":"黄芪","unit":"g","price":0.50,"category":"补虚药"},
  {"code":"dd","name":"当归","unit":"g","price":0.80,"category":"补虚药"},
  {"code":"cs","name":"陈皮","unit":"g","price":0.20,"category":"理气药"}
]
```

JSON 格式为药品对象数组，每个对象包含 code（简码）、name（名称）、unit（单位）、price（单价）、category（分类）字段。

## 第八章 验方设置

### 8.1 验方列表

验方（经验方）是医师在长期临床实践中总结的有效处方，本系统支持将常用验方保存为模板，便于快速调用。进入验方设置：

1. 点击顶部标签栏"【验方设置】"按钮，或按 F3 快捷键，弹出"F3 验方设置"对话框。
2. 对话框顶部显示搜索框（placeholder"搜索验方"）与"新增验方"按钮。
3. 下方为验方列表区，每条验方显示方名、功效、主治、组成药味数等信息。
4. 在搜索框中输入关键字，列表实时过滤显示匹配的验方。

### 8.2 验方创建

创建新验方步骤：

1. 在验方设置对话框点击"新增验方"按钮，弹出验方编辑表单。
2. 填写验方信息：
   - **方名**：验方名称，如"桂枝汤"、"自拟头痛方"。必填。
   - **功效**：验方功效描述，如"解肌发表，调和营卫"。
   - **主治**：主治病证描述，如"外感风寒表虚证"。
   - **组成药物**：药品列表，每味药包括名称、剂量、单位。可从药品库选择或手动输入。
3. 点击"保存"按钮，新验方添加到验方库。

除通过验方设置对话框创建外，还可在处方录入过程中将当前处方保存为验方：

1. 完成一处方录入（无需保存为正式处方）。
2. 点击左侧工具栏"存验方"按钮，或按 F5 快捷键。
3. 系统将当前药品表格中的药品明细保存为验方，提示输入方名、功效、主治等信息。
4. 保存后该验方可通过辨证选方（Alt+1）调用。

### 8.3 验方编辑

修改已有验方步骤：

1. 在验方列表中找到目标验方，点击"编辑"按钮。
2. 弹出验方编辑表单，显示当前验方信息。
3. 修改方名、功效、主治或组成药物（增减药味、调整剂量）。
4. 点击"保存"按钮保存修改。

验方编辑不影响已使用该验方开具的历史处方，历史处方中的药品信息独立保存。

### 8.4 验方调用

验方调用是将验方快速应用到当前处方的操作，有两种调用方式：

#### 8.4.1 辨证选方调用

1. 按 Alt+1 快捷键，弹出"中医辨证选方"对话框。
2. 对话框列出所有验方，每条显示方名（加粗）、功效、主治。
3. 根据患者辨证，点击对应验方。
4. 系统自动将验方组成药物填充到处方药品表格：
   - 每味药的名称、剂量、单位自动填入。
   - 单价从药品库查询最新值（若药品库无此药则单价为 0）。
   - 合计金额自动计算。
5. 处方预览区与金额计算同步更新。
6. 关闭对话框后可在自动填充基础上调整。

#### 8.4.2 直接调用

1. 打开验方设置对话框（F3）。
2. 在验方列表中找到目标验方，点击"调用"按钮。
3. 验方组成药物填充到处方药品表格，效果同辨证选方。

### 8.5 验方库维护建议

验方库是中医师临床经验的沉淀，良好的维护能显著提升开方效率：

1. **方名规范**：使用标准方名（如"桂枝汤"、"麻黄汤"）或自拟方名（如"自拟头痛方"、"经验失眠方"），避免使用模糊名称。
2. **功效主治完整**：详细填写功效与主治，便于辨证选方时快速判断。如"解肌发表，调和营卫"对应"外感风寒表虚证，头痛发热，汗出恶风，鼻鸣干呕"。
3. **剂量规范**：组成药物的剂量应基于临床常用剂量，参考《方剂学》教材或《中华人民共和国药典》。
4. **定期整理**：定期回顾验方库，删除不常用的验方，补充新总结的经验方，保持验方库精炼实用。
5. **带教传承**：老中医可将毕生经验方保存为验方，便于学生调用学习，实现中医经验的数字化传承。
6. **分类管理**：可按病种或证型对方剂进行命名分组，如"头痛方-风寒"、"头痛方-肝阳上亢"，便于辨证选方时快速定位。

### 8.6 验方应用示例

以"桂枝汤"为例，完整的验方创建与调用流程：

**创建验方**：

1. 方名：桂枝汤
2. 功效：解肌发表，调和营卫
3. 主治：外感风寒表虚证。头痛发热，汗出恶风，鼻鸣干呕，苔白不渴，脉浮缓或浮弱。
4. 组成药物：
   - 桂枝 9g
   - 芍药 9g
   - 甘草 6g（炙）
   - 生姜 9g
   - 大枣 3枚

**调用验方**：

1. 患者就诊，辨证为外感风寒表虚证。
2. 按 Alt+1 打开辨证选方对话框。
3. 在验方列表中找到"桂枝汤"，查看功效与主治确认匹配。
4. 点击"桂枝汤"，系统自动将五味药填入处方表格。
5. 根据患者具体情况调整：如头痛甚加川芎 6g，项背强几几加葛根 12g。
6. 设置剂数为 7 剂。
7. 按 F9 保存处方，按 F8 打印。

## 第九章 病例管理

### 9.1 病例列表

病例管理模块以患者为维度，汇总该患者在本诊所的所有就诊处方，便于回顾完整诊疗历程。进入病例管理：

1. 点击顶部标签栏"【病例管理】"按钮，弹出"病例管理"对话框。
2. 对话框顶部显示搜索区，包括患者姓名输入框、起始日期、结束日期、"搜索"与"重置"按钮。
3. 下方为病例列表区，默认显示全部病例。

病例列表显示规则：

- 每条病例对应一个患者的就诊记录汇总。
- 列表按最近就诊时间倒序排列。
- 每条病例显示患者姓名、就诊次数、初诊日期、最近就诊日期等信息。
- 点击某条病例可展开查看该患者的所有就诊处方详情。

### 9.2 病例查看

查看患者完整病例步骤：

1. 在病例列表中点击目标患者条目。
2. 系统展开该患者的所有就诊记录，按时间倒序排列。
3. 每条就诊记录显示处方编号、日期、诊断、药品明细、剂数、金额等信息。
4. 可滚动浏览该患者所有就诊记录，了解病情演变与用药变化。
5. 点击某条就诊记录可进一步查看处方详情或加载到处方录入界面。

病例查看功能对慢性病长期随访患者尤其有用，医师可快速了解患者既往用药与疗效，为本次诊疗提供参考。

### 9.3 病例搜索

病例搜索支持按患者姓名与日期范围组合检索：

1. **按姓名搜索**：在"患者姓名"输入框中输入姓名（支持模糊匹配），点击"搜索"按钮，列表显示匹配患者的病例。
2. **按日期范围搜索**：在"起始日期"与"结束日期"中选择日期，点击"搜索"按钮，列表显示在该时间段内有就诊记录的病例。
3. **组合搜索**：同时填写姓名与日期范围，列表显示同时满足两个条件的病例。
4. **重置搜索**：点击"重置"按钮清空所有搜索条件，列表恢复显示全部病例。

病例搜索帮助医师快速定位特定患者或特定时间段的就诊记录，提升病历检索效率。

### 9.4 病例管理应用场景

病例管理模块在以下场景中特别有用：

1. **慢性病长期随访**：高血压、糖尿病、慢性胃炎等慢性病患者需要长期随访，病例管理可完整呈现患者历次就诊的辨证与用药变化，便于评估疗效与调整治疗方案。
2. **疗效评估**：通过对比同一患者多次就诊的病情变化与处方调整，评估治疗效果，总结经验。
3. **带教讨论**：在带教场景中，可调出典型病例，与学生讨论辨证思路与用药技巧。
4. **复诊准备**：患者复诊前，医师可提前查阅病例，了解既往用药与病情演变，提高问诊针对性。
5. **医疗纠纷举证**：完整的病例记录可作为医疗行为的证据，证明诊疗过程的规范性与合理性。
6. **科研素材**：积累的病例数据可作为临床科研的素材，用于总结用药规律、病种特点等。

### 9.5 病例与处方的关系

病例与处方是"一对多"的关系：

- 一个病例对应一个患者的所有就诊记录汇总。
- 一个处方对应一次就诊的完整诊疗记录。
- 病例管理模块以患者维度聚合处方，便于纵向回顾。
- 历史处方模块以时间维度排列处方，便于横向浏览。
- 两个模块共享底层的处方数据，仅展示视角不同。

病例管理模块的数据来源与历史处方模块一致，均来自 IndexedDB 的 prescriptions 仓库。普通用户仅能查看自己开具的处方对应的病例，管理员可查看全部病例。

## 第十章 数据统计

### 10.1 处方统计

数据统计模块提供多维度处方数据统计分析，帮助诊所管理者了解业务运营状况。进入数据统计：

1. 点击顶部标签栏"【数据统计】"按钮，弹出"📊 数据统计"对话框。
2. 对话框顶部显示统计范围、就诊次数筛选、排序方式三个筛选条件，以及"🔄 刷新数据"按钮。

统计范围选项：今日、本周、本月（默认）、本季度、本年、全部。

#### 10.1.1 核心指标卡

对话框顶部显示四个核心指标卡：

1. **总就诊人数**：统计范围内的去重患者总数。
2. **初诊人数**：统计范围内首次就诊的患者数。
3. **复诊人数**：统计范围内复诊的患者数。
4. **复诊率**：复诊人数占总就诊人数的百分比。

#### 10.1.2 就诊次数筛选

通过"就诊次数筛选"下拉框可按患者就诊次数过滤：

- 全部（默认）
- 1 诊（仅就诊 1 次的患者）
- 2 诊（就诊 2 次的患者）
- 3 诊（就诊 3 次的患者）
- 4 诊及以上（就诊 4 次及以上的患者）

#### 10.1.3 排序方式

通过"排序"下拉框选择列表排序方式：

- 就诊次数（降序）：从多到少排列。
- 就诊次数（升序）：从少到多排列。
- 最近就诊（降序）：最近就诊时间从近到远。
- 最近就诊（升序）：最近就诊时间从远到近。

### 10.2 药材使用统计

药材使用统计帮助医师了解药材使用情况：

1. **常用药材 Top 10**：统计范围内使用频次最高的前 10 味药材，以柱状图形式展示。每味药材的柱状高度反映其使用频次（在所有处方中出现的次数）。
2. **病种分布**：统计范围内各诊断病种的分布情况，以饼图形式展示，直观反映主要病种构成。
3. **就诊趋势**：统计范围内的就诊人次随时间变化趋势，以折线图展示，便于发现就诊高峰与低谷。

图表基于 Chart.js 渲染（Canvas 元素），支持鼠标悬停查看具体数值。

### 10.3 医师工作量统计

医师工作量统计通过处方查阅与数据统计模块结合实现：

1. **患者就诊列表**：统计范围内按患者维度汇总，显示患者姓名、就诊次数、初诊日期、最近就诊日期，可点击"操作"列查看该患者详细处方。
2. **月度统计报表**：按月份汇总统计数据，表格列包括：月份、门诊人次、总收入、总诊疗费、总成本、总利润、总剂数。
   - 门诊人次：当月就诊处方总数。
   - 总收入：当月所有处方总金额之和。
   - 总诊疗费：当月所有处方诊疗费之和。
   - 总成本：当月所有药品成本之和（基于药品成本价计算）。
   - 总利润：总收入 - 总成本。
   - 总剂数：当月所有处方剂数之和。

月度统计报表帮助诊所管理者了解月度业务量与收支情况，为经营决策提供数据支持。

### 10.4 数据导出

数据统计模块支持报表导出：

1. 在"常用药材 Top 10"图表区域点击"导出报表"按钮，弹出文件保存对话框。
2. 选择保存位置与文件名，导出 CSV 格式报表。
3. 报表内容包括：常用药材 Top 10（药材名称、使用频次）、患者就诊列表、月度统计报表等数据。
4. 导出的 CSV 文件可用 Excel 或 WPS 打开查看与进一步分析。

### 10.5 数据备份与恢复

数据统计对话框底部提供"🗄️ 数据管理"区域，包含三个操作按钮：

#### 10.5.1 一键备份

1. 点击"💾 一键备份"按钮（绿色背景）。
2. 系统将全部处方数据、药品库、验方、设置等打包为 JSON 格式备份文件。
3. 弹出文件保存对话框，选择保存位置与文件名。
4. 备份文件包含 HMAC 完整性校验值，防止文件篡改。
5. 建议定期备份并将备份文件拷贝至 U 盘或网盘等异地存储。

备份文件格式说明：

- 文件扩展名：.json
- 文件结构：包含 version（版本号）、exportedAt（导出时间）、data（数据体）、hmac（校验值）四个顶层字段。
- data 字段内含 prescriptions（处方列表）、medicines（药品库）、formulas（验方库）、settings（设置）、users（用户列表，密码以哈希形式保存）等子字段。
- 文件大小取决于处方数量，典型诊所（千张处方）的备份文件约 1-5MB。

#### 10.5.2 恢复数据

1. 点击"📂 恢复数据"按钮（蓝色背景）。
2. 弹出文件选择对话框，选择历史备份文件。
3. 系统读取并校验备份文件完整性（HMAC 校验）。
4. 校验通过后弹出确认对话框，警告恢复操作将覆盖当前数据。
5. 确认后执行恢复，将备份数据写入本地存储。
6. 恢复完成后建议重启软件以确保数据一致。

恢复操作注意事项：

- 恢复操作会用备份文件中的数据完全覆盖当前数据，请确认备份文件为最新版本。
- 若备份文件 HMAC 校验失败，说明文件已被篡改或损坏，系统拒绝恢复并提示错误。
- 恢复后建议立即检查关键数据（如最新处方、药品库）是否完整。
- 跨版本恢复时，系统会自动进行数据结构迁移，兼容旧版本备份文件。

#### 10.5.3 清空数据

1. 点击"🗑️ 清空数据"按钮（红色背景）。
2. 系统弹出二次确认对话框，警告该操作将清空所有处方、药品、验方等数据且不可恢复。
3. 确认后清空全部本地数据。
4. 此操作风险极高，请务必先执行"一键备份"再做清空。

清空数据影响范围：

- IndexedDB 中的 prescriptions 与 settings 仓库全部清空。
- localStorage 中的处方列表、药品库、验方库、设置等数据清除。
- 用户账号数据是否清除取决于具体实现，建议清空前记录用户列表。
- 视频与照片文件不会被清除（保存在独立目录），需手动删除。
- 回收站内容同步清空。

普通用户角色下，"一键备份"、"恢复数据"、"清空数据"按钮自动隐藏，仅管理员可执行数据管理操作。

### 10.6 统计报表解读

#### 10.6.1 复诊率分析

复诊率是衡量诊所患者粘性与疗效的重要指标：

- 复诊率 = 复诊人数 ÷ 总就诊人数 × 100%
- 复诊率高：说明患者对疗效满意，愿意再次就诊，诊所口碑良好。
- 复诊率低：可能原因包括疗效不佳、患者流失、病种结构（如急性病为主）等，需结合病种分布综合分析。
- 行业参考：中医慢性病诊所复诊率通常较高（60% 以上），急性病诊所复诊率相对较低。

#### 10.6.2 病种分布分析

病种分布饼图反映诊所的主要病种构成：

- 饼图按诊断字段统计，每个不同的诊断作为一个病种。
- 建议医师规范填写诊断（包含病名与证型），以获得准确的病种统计。
- 病种集中度高说明诊所有专科特色，可据此优化药品库与验方库。
- 病种分散说明诊所为综合诊疗，需准备更全面的药品。

#### 10.6.3 就诊趋势分析

就诊趋势折线图反映就诊人次随时间的变化：

- 短期趋势（今日/本周）：反映日常业务波动，便于排班管理。
- 中期趋势（本月/本季度）：反映季节性病种变化，如冬季感冒增多、夏季腹泻增多。
- 长期趋势（本年/全部）：反映诊所业务增长情况，评估经营状况。
- 异常波动（如骤增骤减）需结合外部因素分析（如疫情、节假日、天气变化等）。

#### 10.6.4 月度收支报表分析

月度统计报表提供经营决策所需的关键财务数据：

- 总收入 = 当月所有处方总金额之和，反映业务规模。
- 总诊疗费 = 当月所有处方诊疗费之和，反映医疗服务收入。
- 总成本 = 当月所有药品成本之和（基于药品成本价计算），反映药材支出。
- 总利润 = 总收入 - 总成本，反映毛利水平。
- 利润率 = 总利润 ÷ 总收入 × 100%，反映盈利能力。
- 建议每月初查阅上月报表，对比历史数据，分析经营趋势。

如发现利润率持续下降，可从以下方面分析：
- 药品成本是否上涨（检查药品单价设置）。
- 诊疗费是否偏低（评估是否调整诊疗费标准）。
- 病种结构是否变化（高利润病种占比是否下降）。
- 复诊率是否下降（影响患者生命周期价值）。

### 10.7 统计模块使用建议

为获得准确的统计数据，建议遵循以下实践：

1. **诊断规范**：开方时填写规范的中医诊断（病名+证型），如"感冒（风寒证）"而非仅"感冒"，便于病种分布统计的精细化。
2. **医师姓名一致**：同一医师在不同处方中应使用相同的姓名（建议通过用户账号的姓名字段自动填充），避免医师工作量统计出现重复条目。
3. **患者姓名准确**：同一患者使用一致的姓名（避免"张三"与"张三丰"混用），确保就诊次数统计准确。
4. **及时保存**：每次开方后及时保存，未保存的处方不会进入统计数据。
5. **定期核查**：每月初查阅上月统计数据，对比历史数据，及时发现异常波动。
6. **数据导出归档**：定期导出统计报表归档，作为诊所运营的数字档案。
7. **结合实际**：统计数据仅供参考，需结合诊所实际情况（如节假日、季节、疫情等）综合分析，避免片面解读。

### 10.8 统计数据准确性说明

本系统的统计数据基于已保存的处方记录实时计算，具有以下特点：

1. **实时性**：每次打开数据统计对话框或切换筛选条件时，系统从 IndexedDB 实时查询并计算统计数据，确保数据为最新。
2. **完整性**：统计范围覆盖当前用户可见的所有处方。普通用户仅统计自己的处方，管理员统计全诊所处方。
3. **去重逻辑**：总就诊人数按患者姓名去重，同一患者多次就诊仅计为 1 人。复诊人数为就诊 2 次及以上的患者数。
4. **金额计算**：处方金额基于保存时的 totalAmount 字段，加载历史处方时如使用最新单价重新计算，已保存的统计金额不变。
5. **病种识别**：病种分布按诊断字段统计，相同诊断文本归为同一病种。诊断文本不一致（如多一个空格）会视为不同病种。

## 第十一章 用户管理（管理员）

### 11.1 用户列表

用户管理是管理员专属功能，用于维护本系统的登录账号。进入用户管理：

1. 管理员登录后，点击顶部标签栏"【用户管理】"按钮，弹出"用户管理"对话框。
2. 对话框顶部显示当前所有用户列表，每条用户记录显示：
   - 用户名（登录账号）
   - 姓名（医师姓名）
   - 角色（普通用户/管理员）
   - 操作按钮（编辑、查看处方、删除）
3. 列表下方显示"添加新用户"表单。

用户列表从本地存储读取用户数据。每个用户记录包含用户名、密码哈希、姓名、角色等字段。

### 11.2 用户添加

添加新用户步骤：

1. 在用户管理对话框底部的"添加新用户"表单中填写：
   - **登录账号**：用户名，建议使用英文或拼音，如"zhangys"。必填，且不能与已有用户名重复。
   - **密码**：用户初始密码。必填。建议使用 6 位以上字母数字组合。
   - **医师姓名**：用户真实姓名，如"张医生"。该姓名将作为该用户开方时的默认医师名。
   - **角色**：下拉选择"普通用户"或"管理员"。
2. 点击"添加用户"按钮，系统执行：
   - 校验用户名是否已存在。
   - 使用 PBKDF2 算法对密码进行哈希。
   - 将用户记录保存到本地存储。
3. 添加成功后，用户列表实时刷新，新用户出现在列表中。

新用户添加后即可使用其用户名与密码登录系统。

### 11.3 用户编辑

修改已有用户信息步骤：

1. 在用户列表中找到目标用户，点击"编辑"按钮。
2. 弹出用户编辑表单，显示当前用户的用户名、姓名、角色信息。
3. 修改需要变更的字段：
   - **用户名**：可修改，但需确保不与其他用户重复。
   - **医师姓名**：可修改。
   - **角色**：可在普通用户与管理员之间切换。
   - **密码**：如需重置密码，可在编辑表单中输入新密码。
4. 点击"保存"按钮保存修改。

用户名修改后，该用户历史处方中的 createdBy 字段保持原用户名不变（便于追溯），但新处方使用新用户名。

### 11.4 权限设置

本系统通过角色实现权限控制，提供"普通用户"与"管理员"两种角色：

#### 11.4.1 普通用户权限

- 处方录入、保存、打印
- 查看与编辑自己开具的历史处方
- 药品管理（增删改查、导入导出）
- 验方设置（增删改查、调用）
- 病例管理（查看与搜索）
- 数据统计（查看统计数据）
- 修改自己的密码
- 录像与拍照

#### 11.4.2 管理员权限

普通用户的所有权限，外加：

- 用户管理（增删改查用户、分配角色）
- 处方查阅（查阅全诊所所有用户的处方）
- 开机自动启动设置
- 数据备份、恢复、清空

权限通过 permission.js 模块统一管理，登录后根据用户角色调用 applyRuntimePermissions() 方法动态显示/隐藏对应功能按钮。例如，普通用户登录后"用户管理"、"处方查阅"按钮的 display 被设置为 none，数据管理按钮也被隐藏。

### 11.5 修改密码

所有登录用户均可修改自己的密码。修改密码步骤：

1. 点击顶部标签栏"【修改密码】"按钮，弹出"修改密码"对话框。
2. 填写表单：
   - **原密码**：当前登录用户的密码。
   - **新密码**：新设置的密码。
   - **确认新密码**：再次输入新密码以确认。
3. 点击"修改"按钮，系统执行：
   - 验证原密码是否正确。
   - 验证新密码与确认新密码是否一致。
   - 使用 PBKDF2 算法对新密码进行哈希。
   - 更新本地存储中的用户密码哈希。
4. 修改成功后提示，建议重新登录以验证新密码。

密码修改不影响当前登录会话，但下次登录需使用新密码。如忘记管理员密码，需联系软件提供商通过配置文件重置。

### 11.6 查看用户处方

管理员可查看特定用户开具的全部处方，用于业务监管与质量审查：

1. 在用户列表中找到目标用户，点击"查看处方"按钮。
2. 弹出该用户的处方列表对话框，显示该用户开具的所有处方。
3. 列表按时间倒序排列，显示患者姓名、处方编号、日期、诊断、金额等信息。
4. 可点击某条处方查看详情。
5. 点击"关闭"按钮返回用户管理对话框。

此功能便于管理员了解各医师的工作量与开方习惯，发现异常开方行为及时纠正。

### 11.7 用户管理最佳实践

良好的用户管理是诊所信息化管理的基础：

1. **账号命名规范**：用户名建议使用"姓氏拼音+职称"格式，如"zhangys"（张医师）、"linzr"（林主任），便于识别。
2. **角色分配原则**：诊所负责人或前台管理员设置为管理员角色，普通医师设置为普通用户角色，遵循最小权限原则。
3. **密码安全**：初始密码应在用户首次登录后立即修改，避免使用弱密码（如 123456、生日等）。
4. **人员变动处理**：医师离职后应及时禁用或删除其账号（删除前先备份其处方数据），防止未授权访问。
5. **定期审计**：管理员应定期通过"处方查阅"功能审查各用户的开方情况，确保诊疗规范。
6. **账号独立性**：每位医师应使用独立账号登录，避免共用账号，便于责任追溯与工作量统计。

## 第十二章 录像与拍照

### 12.1 录像功能

录像功能用于录制问诊视频，建立患者影像档案，便于复诊回顾与医疗纠纷证据保全。

#### 12.1.1 启动录像

1. 点击移动端底部快捷操作栏的"🎥 录像"按钮，或桌面端对应的录像入口。
2. 弹出"🎥 问诊视频录制"全屏覆盖层，界面布局：
   - **顶部标题栏**：显示"🎥 问诊视频录制"与关闭按钮（×）。
   - **预览区**：中央显示摄像头实时预览画面，右上角显示"切换摄像头"按钮（🔄），用于在前置与后置摄像头之间切换（移动端）。录制中显示红色录制指示灯与"录制中"文字，以及录制计时器（MM:SS）。
   - **控制按钮区**：底部显示三个按钮：
     - "开始录制"：点击启动录制。
     - "停止录制"：录制中可用，点击停止。
     - "保存视频"：录制停止后可用，点击保存。
   - **状态提示区**：底部显示操作提示文字。
3. 点击"开始录制"按钮启动摄像头与录制。系统请求摄像头权限，授权后开始录制。
4. 录制过程中，预览区显示实时画面，计时器显示已录制时长，最大录制时长受 MAX_DURATION 限制。
5. 点击"停止录制"按钮停止录制。
6. 点击"保存视频"按钮保存视频文件。

#### 12.1.2 视频保存与关联

1. 录制完成后点击"保存视频"，系统将视频数据写入本地文件。
2. 视频文件通过 Electron 的 save-video-file IPC 处理器写入磁盘（桌面端）或通过 Capacitor 文件插件写入应用目录（移动端）。
3. 视频文件自动关联到最近保存的处方患者（系统预查最近保存处方的患者姓名，支持先拍照后录入姓名的流程）。
4. 保存成功后提示文件保存路径。

#### 12.1.3 摄像头切换

移动端设备通常有前置与后置摄像头，本系统支持在录制前切换：

1. 点击预览区右上角的"🔄"按钮。
2. 系统切换到另一个摄像头。
3. 切换后预览画面更新。

桌面端如连接多个摄像头，同样支持切换。

### 12.2 拍照功能

拍照功能主要用于舌诊拍照，记录患者舌象变化，辅助辨证论治。

#### 12.2.1 启动拍照

1. 点击移动端底部快捷操作栏的"📷 拍照"按钮，或桌面端对应的拍照入口。
2. 弹出"📷 舌诊拍照"全屏覆盖层，界面布局：
   - **顶部标题栏**：显示"📷 舌诊拍照"与关闭按钮（×）。
   - **预览区**：中央显示摄像头实时预览画面，叠加舌诊引导线 SVG 图形。引导线包含椭圆形舌体轮廓、中线、舌尖与舌侧标记点，以及"伸出舌头，舌尖朝上"的文字提示，帮助患者正确摆位。
   - **切换摄像头按钮**：右上角"🔄"按钮。
   - **拍照按钮**：底部拍照触发按钮。
3. 指导患者伸出舌头，对准引导线轮廓。
4. 点击拍照按钮捕获画面，伴随闪光效果（photo-flash 元素）。
5. 可连续拍摄多张（currentCaptureStep 递增）。

#### 12.2.2 照片保存

1. 拍照完成后，照片通过 Canvas 元素捕获并转换为图片数据。
2. 照片自动保存到本地文件，并关联到最近保存处方的患者。
3. 支持多张连拍，建立完整的舌诊影像序列。

### 12.3 文件管理

录像与拍照产生的文件管理说明：

#### 12.3.1 文件存储位置

- **桌面端**：视频与照片文件保存在 exe 同级目录或 userData 目录下的指定文件夹（通过 get-video-directory IPC 获取）。可通过 open-video-directory IPC 调用系统文件管理器打开该目录。
- **移动端**：文件保存在应用私有目录，用户可通过应用内查看或导出。

#### 12.3.2 文件命名规则

文件名包含患者姓名、时间戳等信息，便于识别与检索。例如：`张医生_20260803_153022.webm`。

#### 12.3.3 文件查看

1. 在患者处方历史或病例管理中，可查看关联的录像与照片。
2. 桌面端可通过"打开视频目录"功能直接在系统文件管理器中查看所有文件。
3. 移动端可通过应用内的文件查看器浏览。

#### 12.3.4 文件清理

视频与照片文件占用磁盘空间较大，建议定期清理：

1. 桌面端可直接在文件管理器中删除不需要的文件。
2. 移动端可在应用设置中清理缓存。
3. 卸载应用会清除所有文件，请提前备份重要影像资料。

### 12.4 录像与拍照应用价值

录像与拍照功能不仅是辅助工具，更具有深远的临床与法律价值：

#### 12.4.1 临床价值

1. **舌诊档案**：舌象是中医辨证的重要依据，定期拍摄舌诊照片可记录舌象变化，辅助判断病情进退与疗效。如舌苔由厚转薄提示湿邪渐退，舌色由暗转红提示瘀血改善。
2. **复诊参考**：复诊时调阅既往问诊视频与舌诊照片，快速回顾患者病情变化，提高问诊效率。
3. **远程会诊**：将问诊视频与舌诊照片发送给上级医师或专家，进行远程会诊，获取第二诊疗意见。
4. **教学示范**：典型病例的问诊视频可作为教学素材，用于中医带教与学术交流。

#### 12.4.2 法律价值

1. **医疗纠纷举证**：完整的问诊视频记录可作为医疗行为规范性的证据，证明医师的诊疗过程符合规范，保护医师合法权益。
2. **知情同意记录**：录制患者知情同意过程，作为知情同意的补充证据。
3. **疗效争议解决**：通过舌诊照片的时间序列对比，客观反映疗效变化，避免疗效争议。

#### 12.4.3 隐私保护注意事项

1. 录像与拍照前应征得患者同意，并告知用途。
2. 影像文件保存在本地，不上传云端，确保数据隐私。
3. 未经患者授权不得将影像资料用于公开场合展示或学术发表。
4. 患者要求删除影像资料时，应及时从文件系统中删除。
5. 诊所应建立影像资料管理制度，明确保存期限与访问权限。

### 13.3 常见问题

#### 13.3.1 登录相关问题

**Q：忘记登录密码怎么办？**
A：普通用户忘记密码请联系管理员重置。管理员忘记密码需联系软件提供商，通过修改 config.json 配置文件中的 users 字段重置。

**Q：登录提示"用户名或密码错误"但确认输入正确？**
A：请检查：1) 用户名与密码大小写是否正确；2) 输入法是否处于英文状态；3) 用户名前后是否有多余空格；4) 是否使用正确的用户名（区分大小写）。

**Q：APP 端每次打开都需要重新登录？**
A：这是 APP 端的安全设计，每次启动主动清除登录态，确保账号安全。如需保持登录请使用桌面版。

**Q：登录后会话保持多久？**
A：登录会话保持 8 小时，超过 8 小时未操作需重新登录。

#### 13.3.2 处方录入问题

**Q：处方无法保存，提示"请输入患者姓名"？**
A：患者姓名为必填字段，请在"姓名"输入框中输入患者姓名后重试。

**Q：药品检索下拉列表不显示？**
A：请确认药品库中已添加药品（通过 F2 药品管理查看）。若药品库为空，请先添加药品或导入药品文件。

**Q：处方编号如何生成？**
A：处方编号自动生成，格式为 YYMMDD+两位序号（如 26080301），保存时由系统自动分配，无需手动输入。

**Q：金额计算不准确？**
A：金额基于药品库中的单价计算，请确认药品单价设置正确。如修改了药品单价，加载历史处方时会按最新单价重新计算。

#### 13.3.3 打印问题

**Q：打印不出内容或排版错乱？**
A：请检查：1) 打印机是否正确连接并设置为默认；2) 纸张尺寸是否与打印模板匹配（建议 A5 或专用处方笺）；3) 打印方向是否与所选模式一致（纵向/横向）；4) 浏览器打印对话框中是否选择了正确的打印机。

**Q：纵向与横向打印有什么区别？**
A：纵向打印为标准 A5 纵向处方笺，适合大多数场景；横向打印内容旋转 90 度，适合特殊纸张或需要更宽书写空间的场景。

#### 13.3.4 数据问题

**Q：数据丢失怎么办？**
A：请检查：1) 是否登录了正确的用户账号（普通用户只能看到自己的处方）；2) 是否在历史处方列表中按患者过滤；3) 是否误删除（检查回收站）；4) 是否有最近的备份文件可恢复。

**Q：如何备份数据？**
A：管理员可在"数据统计"模块点击"一键备份"按钮导出全量数据备份文件，建议定期备份并拷贝至异地存储。

**Q：更换电脑如何迁移数据？**
A：1) 在原电脑执行"一键备份"导出备份文件；2) 在新电脑安装软件并登录；3) 在新电脑执行"恢复数据"导入备份文件；4) 重启软件确认数据完整。

**Q：IndexedDB 数据丢失？**
A：IndexedDB 数据保存在浏览器/Electron 的用户数据目录中，清理浏览器缓存或系统清理工具可能清除数据。请定期备份。如使用便携版，请确保 exe 同级目录可写。

#### 13.3.5 性能问题

**Q：软件启动慢？**
A：首次启动需初始化数据库与加载配置，稍慢属正常。如持续缓慢，请检查：1) 处方数据量是否过大（建议定期归档历史数据）；2) 电脑是否同时运行过多程序；3) 硬盘是否需要清理或碎片整理。

**Q：处方历史列表加载慢？**
A：默认仅加载最近 15 条，可通过"加载更多"逐步加载。如处方总量超过 10 万条，建议定期备份后清理早期数据。

#### 13.3.6 其他问题

**Q：试用版与定制版有什么区别？**
A：试用版有月度处方数量上限（30 张/月），定制版无限制且包含用户管理与修改密码功能。本系统为定制版（clinic_custom）。

**Q：软件无法启动？**
A：请检查：1) 操作系统是否满足最低要求（Windows 7 SP1 及以上）；2) 是否被杀毒软件拦截（请将软件加入白名单）；3) 是否通过命令行添加了调试参数（系统会拦截并退出）；4) 安装包是否完整（建议重新下载安装）。

**Q：录像/拍照功能不可用？**
A：请检查：1) 设备是否连接摄像头；2) 是否授予摄像头权限；3) 摄像头是否被其他程序占用；4) 桌面端确认 video-recorder.js 模块已加载。

**Q：如何联系技术支持？**
A：通过登录界面底部显示的微信号（hktzy1688）联系技术支持。

#### 13.3.7 处方查阅与权限问题

**Q：普通用户看不到其他医师的处方？**
A：这是系统的权限设计，普通用户仅能查看自己开具的处方。如需查阅全诊所处方，请联系管理员使用"处方查阅"功能。

**Q：管理员如何查看特定医师的处方？**
A：管理员点击顶部"【处方查阅】"按钮，在弹出的对话框中通过医师下拉框筛选特定医师的处方。

**Q：删除用户后其处方还在吗？**
A：删除用户后，该用户开具的处方数据保留在数据库中（createdBy 字段保留原用户名），但无法再通过用户列表查看该用户的处方。建议删除用户前先通过"查看处方"导出其处方数据备份。

#### 13.3.8 录像与拍照问题

**Q：录像没有声音？**
A：请检查：1) 设备麦克风是否正常工作；2) 系统是否授予麦克风权限；3) 录制时麦克风是否被其他程序占用；4) 系统音量设置中麦克风是否被静音。

**Q：拍照画面模糊？**
A：请检查：1) 摄像头镜头是否清洁；2) 拍照环境光线是否充足；3) 摄像头分辨率设置；4) 是否对焦完成后再拍照。舌诊拍照建议在自然光或白色光源下进行，避免色温偏差影响舌象判断。

**Q：视频文件无法播放？**
A：视频文件为 WebM 格式，可使用 VLC 播放器、Chrome 浏览器或支持 WebM 的播放器打开。如需在其他设备播放，可使用格式转换工具转换为 MP4 格式。

**Q：录像最大时长是多少？**
A：录像最大时长受 MAX_DURATION 参数限制，具体数值由系统配置决定，通常为 5-10 分钟。如需更长录制，可分段录制多个视频。

#### 13.3.9 辨证选方与验方问题

**Q：辨证选方对话框为空？**
A：辨证选方列表显示的是验方库中的验方。若对话框为空，说明验方库中尚未创建验方，请先通过"验方设置"（F3）创建验方后再使用辨证选方。

**Q：调用验方后单价为 0？**
A：验方调用时系统从药品库查询每味药的单价。若验方中某味药在药品库中不存在或名称不匹配，单价默认为 0。请确保药品库中包含验方所用的所有药品，且名称完全一致。

**Q：存为验方后药品剂量如何处理？**
A：存为验方时，系统保存当前处方药品表格中每味药的名称、剂量、单位。调用验方时按保存时的剂量填充，用户可在调用后调整。

**Q：复诊直调加载的是哪张处方？**
A：复诊直调加载当前患者（处方录入界面"姓名"字段所示患者）最近一次保存的处方。若患者为新患者（无历史处方），则无处方可加载。

**Q：编辑历史处方后原处方还在吗？**
A：是的，编辑历史处方后点击"保存"会生成新的处方记录（新编号、新时间戳），原处方保留不变。这种"编辑即另存"的设计保证处方历史的可追溯性。

## 附录 B：技术架构说明

### B.1 整体架构

本系统采用前后端一体的桌面应用架构，整体分为以下层次：

1. **主进程层（Electron Main Process）**：electron/main.js 作为入口，负责窗口管理、原生 API 调用、文件系统操作、IPC 通信、安全防护等。
2. **预加载脚本层（Preload）**：electron/preload.js 通过 contextBridge 安全暴露受限 API 给渲染进程，避免渲染进程直接访问 Node.js API。
3. **渲染进程层（Renderer Process）**：index.html 及其引用的 JS 模块构成用户界面与业务逻辑，运行在 contextIsolation 启用、nodeIntegration 禁用的安全沙箱中。
4. **数据存储层**：db-adapter.js 统一封装 IndexedDB、localStorage、Electron 文件系统与云端 API 的 CRUD 操作。
5. **共享业务模块层**：auth-core.js、prescription-core.js、permission.js 等独立模块封装公共业务逻辑，桌面端与移动端共享。

### B.2 安全架构

本系统采用多层安全防护：

1. **进程隔离**：contextIsolation=true，nodeIntegration=false，渲染进程无法直接访问 Node.js API。
2. **远程调试拦截**：主进程检测 --inspect、--remote-debugging-port 等调试参数，立即退出程序。
3. **DevTools 拦截**：渲染进程拦截 F12 等开发者工具快捷键。
4. **密码加密**：PBKDF2 哈希 + safeStorage（Windows DPAPI）系统级加密。
5. **登录态校验**：关键业务 API 调用前校验登录状态。
6. **会话超时**：8 小时会话超时机制。
7. **CSP 策略**：内容安全策略限制资源加载来源。
8. **权限运行时控制**：permission.js 根据用户角色动态显示/隐藏功能。
9. **审计日志**：关键操作记录审计日志。
10. **安全防护模块**：security-guard.js 提供额外安全校验。

### B.3 数据存储架构

数据存储采用渐进增强策略，按优先级尝试各存储层：

1. **IndexedDB（主存储）**：数据库名 PrescriptionDB，版本 2，包含 prescriptions（处方）与 settings（设置）两个对象仓库。支持索引与事务，适合大量结构化数据存储。
2. **localStorage（辅助存储与降级）**：用于存储用户会话、记住用户名、药品频次、回收站等小型数据，同时在 IndexedDB 不可用时作为降级方案。
3. **Electron 文件系统（大文件存储）**：用于存储视频、照片、备份文件等大文件，通过 IPC 调用主进程的 fs API。
4. **云端 API（可选）**：db-adapter.js 预留了云端 API 接口，离线版本不启用，云端版本通过 https://tcm-prescription-system.pages.dev/api 访问。
